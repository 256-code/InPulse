# ADR-063：项目列表「未完成」档内统一按最近变更时间排序

- 状态：Accepted
- 日期：2026-10-09
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-046](ADR-046.md) 决策 1 的项目列表行（第一排序键档位与 2026-10-08 修订的第二排序键口径）；沿用 [ADR-043](ADR-043.md) 的项目三态口径与 [ADR-046](ADR-046.md) 决策 3「不为此新增索引与迁移」的结论；模块与功能两层列表不变（仍见 ADR-046 决策 1 表格其余两行）。

## 1. 背景

用户指示（原话）：

> 我希望在项目未完成状态下，每次当项目中有更新，则将项目排序排到最前面

当前事实：

- [ADR-046](ADR-046.md) 决策 1 把项目列表的第一排序键定为「生命周期档位（进行中 `ACTIVE` → 未开始 `NOT_STARTED` → 维护中 `MAINTENANCE`）」；第二排序键（2026-10-08 修订）为「最近变更时间 DESC」，其后按创建时间、ID 降序兜底。
- 档位是第一排序键，于是「未开始」项目永远排在「进行中」项目之后：一个未开始项目无论写入多少更新（生成任务、完成任务、成员变化等），只要它还停在 `NOT_STARTED`，就挤不到任何进行中项目的前面。
- 这与用户「未完成项目一有更新就排到最前」的诉求冲突：只要列表里存在进行中项目，未开始项目的更新就永远不生效。

## 2. 决策

### 2.1 项目档位收窄为两档

`apps/api/src/stats/card-stat-columns.ts` 的排序键（由 `projectLifecycleRankExpression` 更名为 `projectTierRankExpression`）改为：

- `0` = 未完成（`ACTIVE` 进行中与 `NOT_STARTED` 未开始同属一档）；
- `1` = 维护中（`MAINTENANCE`）；
- `2` = `ELSE` 兜底未知脏值，排在最后。

「进行中」与「未开始」不再作为排序档位区分。

### 2.2 未完成档内统一按最近变更时间从近到远

`apps/api/src/modules/projects/postgres-project-query-port.ts` 的 `list` 的 `ORDER BY` 保持不变，仍是「档位 → `projectLastChangeExpression` DESC → `created_at` DESC → `id DESC`」；档位由三档变两档后，`ACTIVE` 与 `NOT_STARTED` 项目在**同一档内**竞争第二键「最近变更时间」，最近有业务变更（生成任务、完成任务、状态流转、发布或作废记录、成员变化等，即该项目动态里最新一条业务事件的发生时间）的项目排最前；没有动态的项目回落 `created_at`。

### 2.3 标签仍按三态渲染

服务端存储状态与项目标签不变：项目仍是 `ACTIVE` / `NOT_STARTED` / `MAINTENANCE` 三态，前端 `apps/web/src/features/common/resource-lifecycle.ts` 的 `projectLifecycleLabel` 等仍按三态渲染「进行中 / 未开始 / 维护中」；只有**排序档位**与展示层归并的 `projectTier` 收窄成两档。ADR-055 / ADR-056 / ADR-057 的「维护中」门禁与自动升级语义不受影响。

### 2.4 不为此新增索引与迁移

延续 [ADR-046](ADR-046.md) 决策 3 的结论：第一排序键仍是由相关子查询算出的 `CASE`，任何索引都无法满足它，追加键的索引也省不掉排序步骤；`MAX(occurred_at)` 仍走既有 `activity_projection_project_cursor_idx` 的反向索引扫描。本 ADR 不新增迁移、不改数据库。

### 2.5 非目标

1. 不改模块与功能两层列表的排序（仍见 ADR-046 决策 1 表格其余两行：进行中 → 未开始 → 创建时间从近到远）。
2. 不改项目标签与徽章的三态渲染，也不改「维护中」的状态机语义。
3. 不引入用户可配置排序。

## 3. 影响

- **服务端**：`apps/api/src/stats/card-stat-columns.ts` 的 `projectLifecycleRankExpression` 更名为 `projectTierRankExpression`，CASE 由 `ACTIVE → 0 / NOT_STARTED → 1 / MAINTENANCE → 2 / ELSE 3` 改为 `ACTIVE → 0 / NOT_STARTED → 0 / MAINTENANCE → 1 / ELSE 2`；`apps/api/src/modules/projects/postgres-project-query-port.ts` 的 import 与 `ORDER BY` 同步更名（其余排序键不变）。
- **契约与生成物**：`packages/api-contract/src/route-registry.ts` 的 `listProjects` summary 同步；`pnpm contract:generate` 重生成 5 个产物，仅 `packages/api-contract/generated/openapi.json` 变更 1 行；`pnpm contract:drift` 与 `pnpm contract:validate`（105 条路由）通过。
- **前端**：`apps/web/src/features/common/resource-lifecycle.ts` 与 `apps/web/src/features/projects/ProjectsPageView.tsx` 只改注释（`projectTier` 与服务端同归并，标签仍按三态渲染；未完成档保持服务端顺序，不再讲「进行中 → 未开始」）。无逻辑改动。
- **测试**：`apps/api/test/projects-read-api.integration.test.ts` 两个列表顺序用例改断言并加步骤——无动态时未完成档内按创建时间从近到远（`ACTIVE` 项目不再压过更晚建的 `NOT_STARTED` 项目）、未完成档内不再分进行中与未开始、维护中档仍垫底。
