# ADR-031：移除 TOTP 两步验证与管理员高风险重认证

- 状态：Accepted
- 决策日期：2026-09-15
- 接受依据：用户在本轮任务中明确选择「①b ②a」——去掉全部 TOTP 验证，并同时取消除登录以外的管理员高风险重认证窗口；数据库侧本期只停用、不删除表与列。
- 替代范围：替代 ADR-016（系统管理员 TOTP MFA 与重认证）的全部内容，并修订 ADR-023 的一次性安全流程 allowlist（9 条收缩为 3 条）。功能设计 §8.1、系统设计 §3.2/§3.3、技术设计 §5.1.3/§7.3.1 中要求 TOTP 的条款随之废止；其余安全与数据基线不变。

## 背景

原基线（ADR-016）要求所有系统管理员强制注册 TOTP，并对高风险动作要求「密码 + 当前 TOTP」在五分钟内重认证（`reauthenticated_at` 与 `mfa_verified_at` 双时间戳）。团队已确定后续统一身份入口为单点登录（SSO），过渡期内不再维护 InPulse 自有的 TOTP 与恢复码能力，因此整体移除该机制。

这是一次明确的安全基线下调：移除后管理员账户没有第二因素，口令泄露即等同于管理员权限被接管；高风险动作也不再要求任何近期重认证。该风险由用户在 2026-09-15 明确选择并承担，记录于此。

## 决策

1. 登录只保留口令因素。预认证 Session 通过 Argon2id 口令校验后直接签发 `AUTHENTICATED` 认证 Session 与新的 CSRF Token，不再存在 `MFA_ENROLLMENT`、`MFA_CHALLENGE`、`RECOVERY_CHALLENGE` 三个中间状态。
2. 删除 TOTP、恢复码与管理员重认证的全部实现：`startMfaEnrollment`、`confirmMfaEnrollment`、`verifyMfa`、`rotateMfaRecoveryCodes`、`consumeMfaRecoveryCode`、`resetAdminMfa`、`reauthenticateAdmin` 七条路由，以及对应的 Zod Schema、Route Registry 条目、权限矩阵条目、OpenAPI、生成客户端、服务、Repository 与前端表单。
3. 高风险管理员操作不再要求重认证窗口。成员管理、用户启停与角色变更、审计读取、记录作废与恢复、模块与功能管理、外链写入等操作仍要求：有效且未撤销的认证 Session、`users.is_admin` 为真、同源与 CSRF 校验、数据库级幂等、不可变审计与既有的 403/404 语义。`user_sessions.reauthenticated_at` 与 `user_sessions.mfa_verified_at` 不再被写入或读取。
4. ADR-023 allowlist 收缩为 `issueCsrfToken`、`login`、`logout` 三条，且必须且只能声明 `securityFlow`；`docs/permissions.md` 的认证安全流程矩阵必须与该集合精确相等，新增例外仍需另立 ADR。
5. 数据库本期只停用不删除：保留 `user_totp_factors`、`mfa_recovery_codes` 两张表，保留 `user_sessions.mfa_verified_at`、`recovery_rotation_generation`、`recovery_rotation_consumed_generation` 三列，保留 `auth_state` 现有四个允许取值。本次不新增迁移，旧版本与新版本代码可在同一迁移窗口内互退；删除表、列、约束与触发器推迟到后续 contract 迁移并单独评审。
6. 生产 Secret `TOTP_KEK_KEYRING_FILE` 与 `TOTP_KEK_VERSION` 不再被 API 读取；阶段 0 尚未发布，随部署配方一并移除，不保留无用途的 Secret 挂载。

7. 契约层 `AuthPolicy` 枚举值 `adminSessionWithReauthentication` 重命名为 `adminSession`（Route Registry、OpenAPI、指纹产物与校验脚本同步）；它表达的门禁已放宽为「有效完整管理员 Session + `is_admin`」，不再含任何近期重认证语义。

## 影响与验证

- 认证：管理员登录链路缩短为「口令 → 认证 Session」，`login` 响应不再返回 MFA 分支的 `authState` 与 enrollment generation。
- 授权：高风险动作的允许条件由「完整管理员 Session + 双时间戳在 5 分钟内」放宽为「完整管理员 Session」。
- 数据：MFA 表与列只保留历史数据，不再读写；不参与搜索投影、审计与备份恢复的业务断言。
- 验证要求：登录链路单测与真实 PostgreSQL 集成测试、CSRF 生命周期、会话清理、权限矩阵（每条路由至少一条允许与一条拒绝用例）、审计只读与上传，以及浏览器 E2E 均按移除后的行为重写；`pnpm contract:validate` 与 `pnpm permissions:check` 必须在新 allowlist 下通过。

## 后续

- SSO 落地时另立 ADR 替换口令因素；`login` 是届时唯一需要替换的认证入口。
- contract 迁移窗口确定后删除 MFA 表、列与 `auth_state` 的多余取值，并同步数据库 Schema、演示种子与备份恢复断言。
