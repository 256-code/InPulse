# ADR-019：Route Registry、权限矩阵与写接口幂等默认值

- 状态：Accepted
- 基线固化：2026-09-04

## 背景

权限、CSRF、幂等、版本和并发策略散落在 Controller 时无法证明全部路由已覆盖；只保护“关键命令”也会遗漏普通编辑和成员变更。

## 决策

Route Registry 是所有 HTTP 路由操作策略的唯一登记点，并与可执行权限矩阵一一对应。所有非安全 HTTP 方法（POST、PUT、PATCH、DELETE）默认 `idempotencyRequired`；普通 GET、HEAD 和纯校验路由登记为 `none`。只有 [ADR-023](ADR-023.md) allowlist 中涉及一次性安全材料的认证流程可以登记 `securityFlow`，其中 `issueCsrfToken` 虽然是 `GET`，仍必须且只能登记 `securityFlow`；其他写路由例外必须在 Route Registry 显式登记原因，并通过新 ADR 评审。

`idempotencyRequired` 的请求摘要包含大写 method、operationId、幂等契约版本、摘要格式与请求 Schema 版本、Schema 解析后的 path 参数和规范 query、规范 Content-Type、Route Registry 声明的全部行为相关请求头及 JCS 规范化 body；使用版本头的路由必须包含 `If-Match`。摘要使用独立、带 key version 的 HMAC-SHA-256，旧密钥保留到对应记录超过 30 天窗口并清理；不得用普通 SHA-256 为低熵密码或验证码形成离线校验器。Cookie、Authorization、CSRF、追踪头、请求关联 ID 与 Idempotency-Key 不进入摘要。

每条 `idempotencyRequired` 路由必须登记带版本的 `idempotencyReplayPolicy`，逐个以互斥联合列出可缓存的 2xx 状态：`body` 分支包含与该状态响应一致的精确 Schema 引用及全部可安全持久化和重放的 body 叶子字段，`noBody` 分支没有 body Schema，且重放时不产生 body 或 Content-Type。响应头不进入通用幂等记录，尤其禁止保存或重放 `Set-Cookie`、Authorization 或 CSRF 相关响应头。`none` 与 `securityFlow` 路由必须把该策略登记为 `none`。

Route Registry 为上述请求与响应策略声明不可复用的幂等契约版本，并把它纳入摘要；请求 Schema、摘要字段、响应 Schema、安全字段或重放授权策略任一改变都必须升级版本。每条路由还登记 `replayAuthorizationPolicy`：`actorOnly` 表示响应不暴露其他资源；`resources` 分支以版本化类型 Schema 提取并持久化响应所暴露资源的最小引用，并绑定当前读取授权器，禁止保存权限快照或显示字段。记录保存精确响应 Schema ref、replay policy 与授权策略版本；旧 Key 在新契约下返回 409，不按旧策略重放。

每次重放都先重新验证当前认证、原操作权限、持久化结果引用中每个资源的当前可读权限，以及路由所需的高风险重认证新鲜度；必须在读取/返回缓存 body 前完成。任一门禁失败则拒绝且不泄露已存状态码或响应，不能仅凭“当前仍可调用 create”推断仍可读取过去创建的资源。

## 影响与验证

写接口必须定义 Idempotency-Key 语义、窗口、摘要格式、契约版本、可安全重放字段与结果资源授权策略；通用记录不得保存或重放任何认证 Secret。CI 检查每条路由字段齐全、所有声明的 2xx 响应均有合法 `body`/`noBody` 安全重放策略及类型化授权上下文、契约变更已升级版本、权限矩阵有允许/拒绝用例，且不存在未备案的例外；集成测试覆盖每类语义输入变化、规范化等价输入、跨部署契约变化、门禁/结果资源权限失效及重放响应投影。
