# ADR-024：迭代记录作废与可审计恢复状态机

- 状态：Accepted
- 基线固化：2026-09-04

## 背景

功能基线要求已发布迭代记录不能物理删除或静默覆盖，同时允许系统管理员在重认证后恢复误作废记录。若 `PUBLISHED` 状态强制要求作废字段为空，`VOID -> PUBLISHED` 只能清除作废历史或违反数据库约束；若恢复直接修改历史版本，又会破坏正式记录不可变原则。因此需要把状态迁移、行级快照和完整历史的职责明确分开。

## 决策

迭代记录只允许以下状态迁移：`DRAFT -> PUBLISHED`、`PUBLISHED -> VOID`、`VOID -> PUBLISHED`。禁止 `VOID -> DRAFT`、已发布内容原地覆盖及任何物理删除；内容修订继续新增不可变版本。

`PUBLISHED -> VOID` 与 `VOID -> PUBLISHED` 均由 `ChangeRecordsModule` 的单域 Application Service 执行。它通过只读 `ProjectAccessQueryPort` / `ModuleQueryPort` / `FeatureQueryPort` 校验归属和父级，不写其他领域聚合；审计、Activity 和 Search 是经横切 WritePort 写入的同库投影，不构成跨域业务写。两种迁移都只允许系统管理员，并要求 5 分钟内的密码 + 当前 TOTP 重认证、去除首尾空白后仍非空的原因、`If-Match` 和 Idempotency-Key。恢复要求项目与模块均为 `ACTIVE`；`FEATURE` scope 另要求目标功能为 `ACTIVE`，`MODULE` scope 没有功能父级。可空的 `task_id` 只表示历史来源，不是恢复门禁。父级按项目、模块、功能顺序取得 `FOR SHARE`，与归档方同序的 `FOR UPDATE` 协调，再以 `status + row_version` 条件更新记录；零行更新统一返回 409。成功迁移递增 `row_version`，并与审计、Activity 和 Search 投影同事务提交；V1.1 未定义作废/恢复通知对象，因此不生成通知。

`status` 是当前状态和详情、统计、搜索、时间线可见性的唯一真相，任何查询或投影都不得用 `voided_at IS NOT NULL` 推断当前仍为 `VOID`。`VOID` 详情对普通项目成员返回 404，不进入普通统计、搜索或时间线；系统管理员仍可读取。作废同事务将同键 Search 及该记录全部既有/新增 Activity 的派生 `visibility_scope/source_status` 更新为 `ADMIN_ONLY/VOID`，普通成员查询始终排除，管理员也只有显式 VOID 筛选时才可搜索。恢复后的 `PUBLISHED` 对项目成员重新可读并重新计入统计，以同一 `(project_id, entity_type, entity_id)` UPSERT Search 为 `MEMBER/PUBLISHED`，把该记录既有 Activity 恢复为 `MEMBER/PUBLISHED` 并追加一条脱敏 `CHANGE_RECORD_RESTORED`，均不得暴露作废或恢复原因。

`voided_at` 与 `void_reason` 是记录行上的“最近一次作废快照”：二者必须同时为空或同时非空，原因不得为空串或纯空白。`DRAFT` 必须为空，`VOID` 必须非空；恢复后的 `PUBLISHED` 保留这对字段。后续再次作废可以更新最近快照，但每一次作废与恢复的操作者、原因、时间、前后状态和请求关联都必须分别进入不可变审计事件 `CHANGE_RECORD_VOIDED` / `CHANGE_RECORD_RESTORED`，完整历史以审计链为准。恢复在 `change_records` 行上只修改 `status`、`row_version` 与 `updated_at`，不得改变 `code`、`published_at`、`current_version`、`current_payload`、任一版本行、`task_id`、`module_id`、`feature_id`、`scope_type` 或外链。

同一 Idempotency-Key、相同摘要与相同幂等契约版本的重试，只有在当前认证、系统管理员权限及 5 分钟双时间戳重认证门禁仍通过后才按通用协议重放首次 2xx；门禁失败时拒绝且不得泄露已存响应。新 Key 对已经 `PUBLISHED` 的记录再次恢复、对已经 `VOID` 的记录再次作废，或任何 `If-Match` 冲突均返回 409，不产生部分更新。

## 影响与验证

数据库约束必须允许 `PUBLISHED` 同时表达“从未作废”和“作废后恢复”，但拒绝作废时间/原因只出现一个或原因为空白的行。真实 PostgreSQL 与 API 测试必须覆盖全部合法迁移、非法迁移、按 scope 区分的父级不可用、VOID 详情/统计/搜索/时间线权限、普通成员迁移拒绝、重认证失败或过期、双 Key 版本竞争、门禁通过后的同 Key 重放、新 Key 重复操作、二次作废/恢复、事务回滚、字段与版本内容不变、`row_version` 递增、搜索 UPSERT 与脱敏 Activity，以及每次成功迁移恰有一条审计；验收项见[测试矩阵](../test-matrix.md)的 `STATE-001`～`STATE-003`。
