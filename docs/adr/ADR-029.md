# ADR-029：Nest 运行期采用自研 Zod Pipe 与响应 Serializer

- 状态：Accepted
- 基线固化：2026-09-09
- 关联：[ADR-004](ADR-004.md)、[ADR-019](ADR-019.md)、[ADR-026](ADR-026.md)、[ADR-027](ADR-027.md)、[ADR-028](ADR-028.md)
- 替代：无（[ADR-026](ADR-026.md) 第「升级时」第 4 条对 12.x 原生替换的评估仍保留）

## 背景

`AGENTS.md` 第 4 节与 [ADR-027](ADR-027.md) 第 7 条此前把「Nest Zod Pipe/Serializer 组合和运行参数」列为阶段 0 未定案项。`apps/api` 已落地 Schema Registry、Route Registry、OpenAPI 与生成客户端，但只有把这两份注册表接入 Nest 请求/响应管道，才能满足技术设计 §4.1 第 11、12 条与统一错误模型 §4.2。

阶段 0 需要先形成决策记录，而不是让实现默认成为既成事实。NestJS 11.2.3 不导出 `StandardSchemaValidationPipe` 与 `StandardSchemaSerializerInterceptor`，因此本 ADR 定案采用零新增运行时依赖的自研组件。

## 决策

1. **Controller 只绑定 operationId**：每个 handler 使用 `@Operation("operationId")` 声明 Route Registry 的稳定操作标识；请求参数使用 `@ContractBody`、`@ContractQuery`、`@ContractPath`、`@ContractHeaders`，由运行期从 Route Registry 解析 schemaRef，再引用 Schema Registry。Controller 不再手工导入并重复解析业务 Zod Schema。
2. **请求 Pipe**：`ContractValidationPipe` 以 `operationId + part` 读取注册表并执行 `safeParse`；失败统一抛 `ContractValidationError`，由全局过滤器输出 422 `VALIDATION_FAILED`，不泄漏 Zod 内部格式。body/query/path 的 `.strict()` 语义保留；headers 只提取 Schema `shape` 声明字段，避免 Express 的 `host`、`connection` 等真实头部被当作未知字段。
3. **响应 Serializer**：`ContractResponseInterceptor` 读取 `@Operation` 元数据和实际 `response.statusCode`，按 Route Registry 响应状态选择 Schema，校验成功时返回 `parsed.data`（Zod 默认剔除未知字段）；`noBody`/未登记响应状态不校验。响应校验失败抛 `ContractResponseError`，全局过滤器输出统一 500 `INTERNAL_ERROR`，不返回校验细节或数据库实体。
4. **统一错误模型**：全局 `@Catch()` Filter 转换 `ContractValidationError`、显式 `ApiHttpError`、Nest `HttpException` 与未预期异常；所有错误响应都包含 `{ code, message, details, requestId }` 并设置 `X-Request-Id`。不向客户端返回 Nest 默认错误体、堆栈、内部校验文本或未匹配路由的 method/path。
5. **顺序**：非安全方法先经过 `StrictSameOriginGuard` 做 Origin/Referer/Fetch Metadata 校验，随后才执行参数 Pipe，因此 403 优先于 422；Controller 内层既有同源校验继续保留作为防御性兜底。
6. **运行参数**：operationId 保存为 handler 的 Reflect metadata；Interceptor 按响应真实 statusCode 选择 Schema；不引入全局 JSON Schema 校验库或第三方 Nest zod 包，不产生 manifest/lockfile 变更。

## 影响与验证

已给当前 23 条已登记路由的全部 Controller handler 添加 `@Operation`，并把 body/query/path/headers 参数接入 Contract decorator；Controller 扫描现在同时校验 method、path 与 operationId，`contract:drift`、`contract:validate`、`permissions:check` 均通过。

本地验证：

- `pnpm --filter @inpulse/api typecheck` 通过；
- `pnpm --filter @inpulse/api test:unit` 52 文件 243 例通过，其中新增契约 Pipe/Serializer/Filter/HTTP 冒烟 4 文件 18 例；
- `contract-runtime.http.test.ts` 覆盖有效请求、422 统一错误、响应校验失败 500、未匹配路由 404、同源 Guard 403；
- `pnpm --filter @inpulse/api-contract test:unit` 59 例通过；
- `pnpm contract:drift`、`pnpm contract:validate`、`pnpm permissions:check` 通过；
- `pnpm check` 全绿；真实 PostgreSQL API 集成 28 文件 124 例、database 集成 13 例、Playwright 8/8 通过。

GitHub Actions 尚未因本 ADR 执行；ADR 只定案运行期组合，不改变依赖版本或数据库策略。

## 后续

若未来升级 NestJS 12.x 并评估原生 Standard Schema Pipe/Serializer，必须按 [ADR-026](ADR-026.md) 的触发条件与工作清单执行，并以新 ADR 替代本记录。
