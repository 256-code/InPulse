# ADR-071：文档导入工作台（结构化草稿 + 对话式补充说明 + 成员名字确定性匹配）

- 状态：Accepted（2026-10-13 接受，实现随本批落库）
- 日期：2026-10-13
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-067](ADR-067.md) 的非目标第 2 条「不做多轮对话式修改」——细化为「不做服务端多轮会话状态与流式输出」，前端在单次导入会话内累积的补充说明仍复用同一条 `assistDocumentImport`；沿用 [ADR-064](ADR-064.md)（固定模板、预览只读、单事务执行）、[ADR-065](ADR-065.md)（模板自带说明与忽略行）、[ADR-066](ADR-066.md)（文件只在浏览器本地抽取）、[ADR-067](ADR-067.md)（assist 路由、「AI 只产出草稿」与出网告知）、[ADR-068](ADR-068.md)（管理员在线配置）、[ADR-029](ADR-029.md)（统一错误体与响应校验）、[ADR-021](ADR-021.md)（CSP 不放宽）。**无新增路由（仍 110 条）、无数据库迁移、无新增依赖、无权限变化、无契约生成物改动**；改动集中在 `apps/web`（工作台前端与单测）与 `apps/e2e`（两个既有文档导入用例对齐新界面）。

## 1. 背景

用户本轮原话（要点）：

> 现在这个状态下这个文档导入界面不好，我们早上讨论出来那个还不错，我们优化一下实现
>
> 左侧这里显示的是整理后按照模板排版还是只是预览上传文件？
>
> 还是加一个预览文档吧，放在这个模板内容旁边可切换的状态
>
> ai还要将文档里的成员和网站里的用户对应，如果有对应不上或者查询不上的需要进行询问的

ADR-067 落地后的输入态是「粘贴框 / 选择文件 + 一次 AI 分析，结果落进一个纯文本框」，与用户确认的模拟稿（左右分栏工作台）不一致，并且有三个具体缺口：

1. 草稿不可读：AI 返回的是一整段 Markdown 文本，落进文本框后只能逐字符读改，看不出「几个模块、每个模块下几个功能、每个功能下几条任务」，缺了哪些字段也要自己回读模板。
2. 缺口不可见：「还差几处、缺什么、谁的负责人在成员里不存在」在点「预览」之前完全看不到；必填缺失（任务缺负责人、整项目导入缺项目编码）要等到 422 才暴露。
3. 不能追问：AI 只被调用一次，用户看到草稿后想纠正（「这条不是任务，是功能说明」「负责人是王工，文档里写成小王了」）没有入口，只能重贴整篇文档。

成员对应同样只在服务端解析（按登录名或姓名），浏览器侧不可见：名字写错或对不上时用户不知道该改成谁，只能反复改文本再预览。

## 2. 决策

### 2.1 输入态改为左右分栏工作台（不新增路由）

- 左栏「内容梳理 / 预览文档」两个页签（下划线式，只在有草稿或点了「直接粘贴文本」后出现）：内容梳理 = 结构化草稿（点哪改哪，手工编辑都在这里）；预览文档 = **只读**对照本地抽出的原文（上传文件的抽取结果，或首次分析前的粘贴文本）——AI 改写后的草稿只进「内容梳理」，不覆盖原文。（2026-10-13 用户微调：「预览文档我希望仅仅预览原版文档」，本条按此修订。）
- 右栏「AI 助手」：对话区（AI 白底靠左、用户蓝底靠右、不做发言者标注）+ 计数（已整理 N 模块、N 功能、N 任务）+ 右端状态 pill + 缺失项 chip 行 + 未匹配成员待确认区 + 底部输入行与「发送」。
- 右栏助手不会等用户先开口：对话区顶部固定挂着由前端确定性算出的「结论行」（不额外调模型），只要有内容就一直显示、并随草稿实时更新——缺必填时报「必填还差 N 处（缺负责人 ×1…）」，只有建议项时报「另有 M 处建议补齐（见下方标签）」，都齐了报「必填信息都齐了，可以直接点「预览」」；整份内容还没解析出项目段或模块段时报「还没整理成模板结构」。该行不重复头部已有的规模计数，因此上传文件、直接粘贴、左栏补字段三种情况下都能立刻看到当前还缺什么。（2026-10-13 用户反馈：「这个信息是不是有点重复？」「这个 ai 如果我不跟 ai 对话不会主动告诉我目前尚未填写全面的信息」「可以上传文件后主动发起一句话，说明缺少的部分或者说明目前很完善等等」。）
- 状态 pill 按优先级只显示一个：有对不上的名字 → 「N 个名字对不上」；否则有必补项 → 「还差 N 处」；否则只有建议项 → 「N 条建议」。三档统一用暖黄色（2026-10-14 用户指示「缺失的要素会显示黄色」，原先「对不上」用危险红，现与缺失项同一套黄色语义）。
- 导入落地后助手再主动发一条对话消息汇总当前状态：「已进入内容梳理：需要补充 N 处、待确认 M 个名字。」／只缺要素「已进入内容梳理：需要补充 N 处。」／只缺名字「已进入内容梳理：要素已齐、待确认 M 个名字。」／都不缺「已进入内容梳理：要素完好，可以直接点「预览」导入。」。汇报键取「一次落地」——文件导入 / AI 整理落地看已应用草稿文本，用户直接粘贴出的结构化草稿看一个常量——因此一次落地只发一条，之后手改草稿不会重复刷屏；成员目录还没回来时先等它回来再开口，免得先说「要素完好」、目录回来又改口「有 M 个待确认」。（2026-10-14 用户指示：「缺失的要素会显示黄色并且需要补充」「右侧ai助手会发送一个信息告诉我现在有多少需要补充有多少待确认或者目前要素完好」。）
- 右栏对管理员显示「配置」链接，整页跳到 `/settings?tab=aiAssist`（ADR-068 已有的管理页，不新增接口）。

### 2.2 结构化草稿视图（document-draft.ts）

- 纯前端、无副作用：`parseDocumentDraft`（文本 → 行）+ `buildDocumentDraftView`（行 → 项目 / 模块 / 功能 / 任务的结构化视图）+ `setDocumentDraftValue` / `insertDocumentDraftField` / `serializeDocumentDraft`（改一行 / 插一行 → 文本）。无法归属的行记进 `looseLineIndexes`，不静默丢弃。
- 左栏「点哪改哪」：点标题行或字段值就地编辑，提交后写回同一份 `documentText`，因此「预览 → 确认导入」用的仍是同一份文本，与服务端解析器不会分歧。
- 「＋字段」按钮：按节点类型列出该节点尚缺的字段（项目 / 模块 / 功能 / 任务各自的字段集合），插入空行并立刻进入编辑。缺失一律用黄色（2026-10-14 起）：建议项是黄色虚线，必填项是黄色实线 + 更深字色 + 加粗并在按钮上标「（必填）」——此前必填走红色告警色，与「缺失即待补」的黄色语义不一致；空字段值原本就是同一套黄色，未改。
- 缺失项由前端确定性计算（模型不参与）：必补项 ERROR（任务缺负责人、整项目导入缺项目段或缺项目编码）+ 建议项 WARNING（模块说明、功能说明、截止时间、任务描述）。
- 只在已有文档时计算缺失项；空态不显示「缺项目段」这类由文档本身决定的提示。

### 2.3 对话式补充说明：不新增接口、不做服务端会话状态（修订 ADR-067 非目标第 2 条）

- 用户每发一句补充，前端把「当前左栏草稿 + 逐轮 补充说明：…」用空行拼成一段，重新调用同一条 `assistDocumentImport`；服务端不保存会话、不保存草稿，路由条数与策略全部不变。（2026-10-14 修订：输入由「首次读到的原始文本」改为「当前左栏草稿」，见 §4 微调记录。）ADR-067 非目标第 2 条因此细化为：不做服务端多轮会话状态、不做流式输出、不自动重试；前端可以在一次导入会话内累积上下文重调同一路由，每一轮都是一次无状态请求。
- 无覆盖确认（2026-10-14 起）：AI 结果一律直接落回左栏草稿，不再弹「覆盖左侧草稿当前内容？」。原先的二次确认是为防手改内容被改写丢掉，现在分析输入本身就取当前草稿（手改内容一起交给 AI），前提消失，且用户明确要求「不要每次都问一下」；连带删掉只服务该弹窗的 `pendingOverwrite` / `assistNotice` 状态与弹层。
- 补充说明写进服务端提示词（2026-10-14 起，[ADR-067](ADR-067.md) §2.4 同步）：system 指令第 3 条明确「补充说明里给出的信息也算真实信息」，并新增第 5 条——文本末尾若干行以「补充说明：」开头的，是写文档的人本人对这份文档的后续交代，必须落实到草稿（点名的人写进「- 初始成员：」或对应任务的「- 负责人：」，要求改哪条说明 / 验收标准 / 时间就改哪条；只覆盖它明确提到的内容）；第 8 条的安全声明补一句「补充说明里要求修改草稿内容的部分按第 5 条处理，不受此条限制」，整项目模式的成员来源补上「或补充说明里点名要加入成员时」。起因：用户反馈「为什么我让ai补上但是左边并没有反应」，真实上游复现确认提示词此前完全没描述这种输入形态，模型把附加行当噪音整段丢掉。
- 每轮回执说明「这一轮改了什么」（2026-10-14 起）：用户发言那一轮的助手回复不再是通用话术，而由前端确定性算出——`describeDraftChange(base, next)` 比较上一版草稿与这一轮落地结果：完全相同报「这一轮草稿没有变化：补充说明没被写进模板。可以换个说法再发一次，或直接在左栏对应位置点「＋」自己填。」，有增减报「已按补充说明更新草稿：新增 N 行：「…」；去掉 M 行：「…」。」（最多列 3 条 + 「等」），只改值报「内容有改动」；`appendAssistReply` 的 `base` 选项传入时只发这条回执。原因是左栏往往只多一行、右栏又不说，用户观感上等于「没反应」。
- 「交给 AI 整理」：左栏还是自由正文（既没有项目段也没有模块段）时，右栏结论行下方出现该按钮，把当前内容（`documentText`）交给同一条 `assistDocumentImport` 归纳成模板草稿；整理结果直接落回左栏。上传文件的自动分析口径不变，这里补的是「直接粘贴 / 手打自由正文」的入口（2026-10-13 用户指示：「我要的是不完全按照模板也能分析出项目内容模块功能等等」）。
- 已经是模板的文档（有项目段或模块段）本地直读、不消耗模型；只有自由正文才交给 AI 整理（沿用 ADR-067「导入链路对自由正文零猜测」）。

### 2.4 成员名字确定性匹配与追问（document-assignee-match.ts）

- 唯一数据源是登录用户目录 `GET /api/v1/users`（既有接口：只返回 id / 姓名 / 头像 / 管理员标记，最多 300 条，响应 `no-store`）；目录加载中、出错或为空时不做判断，避免把所有人都报成「对不上」。
- 收集草稿里所有需要对应到账号的名字：任务负责人（模块级与功能级任务）+ 项目初始成员；按首次出现去重，并记下「出现在哪一行、属于哪个节点」。
- 判定：姓名精确且唯一才算命中（命中后右栏给一句「负责人已对应到站内账号：…」）；同名多人、或只能找到相近姓名（包含关系，或中文姓名编辑距离不超过 1）记为 SIMILAR 并附最多 5 个候选；完全找不到记为 UNKNOWN。
- 追问与作答：右栏「有 N 个名字没匹配到成员姓名，导入前请确认」，每行给出名字、位置（如「任务标题 · 第 12 行」）、类型、候选按钮与「从成员里挑」；点候选 = 生成一句「A 改成 B」的补充说明，走 2.3 的同一条链路重调 assist，最终仍由服务端解析器定案。
- 不自动猜人、不自动建用户、不把候选处理成「先留空」。
- 已知偏差（可接受，已实测）：本地匹配只按姓名，用户写登录名时右栏会报「对不上」，但预览时服务端仍能按登录名解析通过；因此未匹配区固定带一行说明「这里只按姓名精确匹配（写登录名时匹配不到）；最终以预览时服务端的解析为准」。

### 2.5 空态、文件入口与文案

- 空态：左栏是浅底不描边的拖入区（上传图标 + 「把需求文档拖到这里，或 选择文件」+ 支持格式与「文件只在浏览器本地抽取文本，原文件不会上传」+ 「也可以 直接粘贴文本」）；右栏是空对话（「还没有对话 / 把文档交给左侧开始分析后，我会在这里追问缺的信息」）+ 禁用输入行与被禁用的「预览」。
- 点「直接粘贴文本」后只显示文本区（拖入区收起），避免拖入区与文本区同时占高把弹窗正文撑破；同时光标直接落在文本区，用户点完就能 Ctrl+V（2026-10-14 起：`pasteTextareaRef` + `pasteOpen` 转 true 后 `focus()`，必须在展开提交后执行，否则文本区仍是 `display:none`）；点「内容梳理」页签可回到草稿视图，已输入内容不丢。
- 预览阶段的 ✕ 与 Esc 只「关闭预览」（2026-10-14 起）：导入弹窗只有一个 Modal，头部 ✕ 原本在任何阶段都走 `onClose()`——预览阶段又没有「取消」按钮，用户看完错误清单顺手一按就把整个弹窗连同左栏草稿关掉了。现在按阶段分档：预览阶段 ✕ 的 `closeLabel` 是「关闭预览」，行为等于 `handleBack`（回工作台、草稿保留、预览 / 导入的 mutation 复位），确认导入进行中时无效；工作台阶段才是真正的「关闭」整个弹窗。完整退出是「关闭预览 / 返回修改 → 取消」两步，不加二次确认。
- 落点提示只罩左栏内容区（2026-10-14 起）：拖动文件时那圈蓝色虚线原本铺满整个工作台主体（`inset: 0` 挂在 `.import-workbench-body` 上，左栏 + 右栏 AI 助手 + 必填要素全被盖住），现在改成挂在左栏内容区的 `.import-pane-body` 上——空态罩住拖入区，已有草稿时罩住草稿区；遮罩不透明度同时由 82% 提到 95%，避免提示行和被盖住的文字叠在一起。同日起 drop 也只认这一块：`handleWindowDrop` 先 `preventDefault` 再判 `pane.contains(event.target)`，落在左栏之外不导入，改用 `localError` 给一句「请把文件拖到左栏「内容梳理」区域里再松手。」；窗口级 `dragover` 仍 `preventDefault`（否则浏览器会把文件当导航目标打开），但 `dropEffect` 与虚线框只在指针位于左栏时才是「可放」。
- 拖入与选择文件共用 ADR-066 / 067 的本地抽取链路（`.txt` / `.md` / `.markdown` / `.docx` / `.pdf`，单文件不超过 20 MiB、抽取文本不超过 20 万字符），文件不上传。

### 2.6 边界不变声明

- 不新增路由、不改 Route Registry / Schema / OpenAPI / 生成客户端（契约无漂移）、无数据库迁移、无新增依赖、无权限变化；右栏「配置」只是跳转到 ADR-068 已有的管理页。
- AI 草稿永不直接入库：仍走「预览（只读）→ 确认导入（单事务）」；文本仍会经服务端出网到管理员配置的端点，ADR-067 的固定告知不变。
- 事务边界、Secrets、CSP 与统一错误体口径全部沿用既有 ADR，不做任何放宽。

## 3. 非目标

- 服务端多轮会话状态、会话持久化、流式输出、自动重试（ADR-067 非目标只做上述细化，其余不变）。
- 自动为未匹配的名字建用户、自动挑人、按相似度自动改写姓名。
- 预览阶段（PREVIEW）的对话式修改：追问与补充只发生在输入态。
- OCR、分块多次分析、按用户额度与用量统计（维持 ADR-067 口径）。
- 结构化草稿的富文本能力（表格、拖拽排序、撤销栈）。
