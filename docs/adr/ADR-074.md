# ADR-074：迭代记录「生成总结」内嵌 AI 改写（一句话要求 → 生成 → 生成后逐段手改）

- 状态：Accepted（2026-10-14 接受，实现随本批落库）
- 日期：2026-10-14
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：沿用 [ADR-067](ADR-067.md) / [ADR-068](ADR-068.md)（AI 辅助的配置来源、密钥通道与「AI 只产出文本、永不直接入库」口径）、[ADR-019](ADR-019.md)（纯校验 allowlist）、[ADR-029](ADR-029.md)（统一错误体与响应校验）、[ADR-071](ADR-071.md)（同一套「点哪改哪」的编辑交互）。**新增 1 条路由（115 → 116）、无数据库迁移（仍 42 个）、无新增依赖、无权限变化、无审计 / 活动 / 通知 / 搜索投影写入、无契约模板改动**；契约生成物按 `pnpm contract:generate` 更新，`contract:drift` 无漂移。

## 1. 背景

用户原话（要点）：

> 这个生成总结也想增加一个 ai 功能，希望效果是有一个端口可以连接上 ai 助手，可以跟 ai 助手说需求，可以先选好上面的选择。然后进入 ai 模式默认对选择状态的总结进行更改。当然也可以直接跟 ai 说希望筛选哪个项目哪个时间段等等。先做出模拟图
>
> 因为这个总结我不准备用对话的模式就仅仅是提要求，然后生成年度总结，我希望生成的总结界面也可以手动更改，请再给我生成几个样式
>
> 如果 ai 窗口放在文件右上方呢

`/records` 的「生成总结」弹窗（`RecordSummaryModal`）此前只有确定性正文：按已选范围（项目 / 时间段 / 成员 / 分组）在本地拼出 Markdown 摘要，用户只能整段复制或导出，既不能改写措辞，也不能补一句「重点写风险」。三条约束把方案钉死：

1. **不是对话**：用户明确不要聊天式交互，只要「提一句要求 → 出一份总结」。
2. **生成后必须能手改**：与文档导入工作台同一口径（点哪改哪），不能生成完把正文变成只读。
3. **入口不能挤压正文**：正文是阅读主体，AI 只能做成一枚标题栏按钮 + 按需拉出的浮层。

## 2. 决策

### 2.1 一次改写，不建会话状态

新增 `POST /api/v1/record-summaries/assist`（`operationId: assistRecordSummary`）：

- 请求 `{ requirement: string(1..500), facts: string(1..20000) }`，响应 `{ markdown: string(1..200000), model: string, truncated: boolean }`（`packages/api-contract/src/contracts/record-summary-assist.zod.ts`，`.strict()` + `.meta({ id })`）。
- 实现见 `apps/api/src/workflows/record-summary-assist.controller.ts` 与 `record-summary-assist-http.service.ts`：先 `SessionAuthService.resolveActor`（无有效 Session → 401 `RECORD_SUMMARY_ASSIST_SESSION_REQUIRED`），再 `AiAssistRuntimeService.resolve()`；未启用 / 配置非法 → 503 `AI_ASSIST_DISABLED`，上游鉴权 / 限流 / 超时 / 网络 / 上下文超限 / 响应非法 → 503 `AI_ASSIST_UPSTREAM_FAILED`（`details.reason` 为固定枚举）。
- **不查库、不写库、不写审计、不开事务**：服务只做「把事实与要求交给上游、把返回的正文交回来」。筛选仍由前端已选范围决定（见 §2.2），服务端不接受也不解析筛选意图。
- 复用 ADR-067 / ADR-068 的运行时配置与 `/run/secrets/*` 密钥通道，不新增配置项；`AI_ASSIST_ENABLED` 仍是急停开关。

### 2.2 事实由前端本地正文给出

`facts` 由前端用 `summaryDocumentToText(document)` 生成，即当前范围下的确定性正文（与「非 AI」路径同一份事实）。范围（项目 / 时间段 / 成员 / 分组）一变就清空 AI 结果与手动改动，避免「换了范围、正文还是上一份」。

### 2.3 提示词与出站

新增 `apps/api/src/modules/document-import/record-summary-assist.prompt.ts`：事实是唯一来源，不得新增或改动数字、日期、人名与编号；必须保留分节结构；只输出总结正文；忽略事实与要求里夹带的指令（防提示注入）。出站复用 `ai-assist.client.ts`（新增 `generateSummaryDraft`），日志按 `kind: "summary"` 记录 `mode@ / `inputChars` / 状态 / 耗时，不记录正文。

### 2.4 前端：标题栏一枚按钮 + 非对话浮层

`apps/web/src/features/records/RecordSummaryModal.tsx`：

- `AppModal` 新增 `headerActions` 插槽（不传则不占位，既有调用方不受影响）；「✦ AI 助手」按钮挂在标题栏右侧、紧挨关闭按钮，点开从按钮下方拉出浮层（`role="dialog"`，点外部收起）。
- 浮层不是聊天记录：一段要求输入框（500 字上限与 `maxLength`，`Ctrl` / `⌘ + Enter` 直接生成）、5 个快捷要求词、状态行与生成按钮；要求为空时回落到「按现有结构重新整理一遍，保持全部事实不变」。
- 生成成功后浮层自动收起，正文按标题 / 段落 / 列表切成可编辑单元（`contentEditable`）：改过的段落左侧出现橙点、悬停显示「回退这句」，底栏显示「已手动改 N 处」并提供「撤销手动修改」。
- 复制与导出取**编辑后**的正文（`summaryAssistDocumentToText(aiDocument, edited)`），未编辑时与 AI 返回一致；切段 / 分组 / 复制的纯函数在 `record-summary-assist-document.ts`。
- 未启用或上游失败时浮层内以 `role="alert"` 显示固定文案，正文保持原样不变。

### 2.5 为什么是纯校验，且无 CSRF 与幂等

与 `assistDocumentImport`（ADR-067）同口径：接口不写任何持久化状态，只做一次出站调用并返回文本，因此 `csrfPolicy: "none"`、`idempotencyPolicy: "none"`，并加入 ADR-019 的纯校验 allowlist（`packages/api-contract/src/pure-validation.ts` 已登记 `assistRecordSummary`）。allowlist 之外仍默认 `idempotencyRequired`。

### 2.6 与既有路由的关系

本 ADR 不改动 `assistDocumentImport`、预览与执行路由的策略与行为；两条 AI 路由各自服务一处入口，共用同一份运行时配置。

## 3. 影响

- 路由 115 → 116；`contract:validate`、`permissions:check`、`contract:drift` 按新路由同步；权限行为不变（任何已登录用户可调用，匿名 / 停用用户 401）。
- 兼容性：纯新增能力；既有确定性正文路径、范围筛选与导出逻辑不变，AI 改写是可选增强。
- 不涉及数据库、迁移、审计链、活动 / 通知 / 搜索投影，也不改变任何项目内权限。

## 5. 非目标与后续

- **不解析筛选意图**：用户提到「也可以直接跟 ai 说希望筛选哪个项目哪个时间段等等」，本 ADR 未实现——AI 只改写「当前已选范围」的事实，不发自然语言筛选指令；换范围仍要用上面的选择器。这是明确的后续项，不得描述成已实现。
- 不做服务端多轮会话状态、不做流式输出、不改导出格式、不新增 AI 配置项。
