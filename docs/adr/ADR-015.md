# ADR-015：同步 CSRF Token 与有限重签

- 状态：Accepted
- 基线固化：2026-09-04

## 背景

Cookie Session 需要覆盖首次匿名登录、Session 轮换、刷新和多标签场景的 CSRF 闭环。

## 决策

采用同步 Token；提供匿名与已登录签发端点。除下述登出恢复分支外，所有非安全方法都必须携带与当前有效 Session 绑定的 `X-CSRF-Token`，数据库只存有限数量的短期 Token 哈希。客户端仅在服务端明确表示 CSRF 校验失败且业务/安全状态尚未消费时重签并最多重试一次；`idempotencyRequired` 及版本化路由保留原 Idempotency-Key/If-Match，`securityFlow` 不发送业务 Idempotency-Key，而按 [ADR-023](ADR-023.md) 的逐操作机制与恢复路径执行。

`logout` 首次调用在 Session 有效时仍必须验证 CSRF 并撤销 Session。Session 已无效、已撤销，或首次登出成功但响应丢失后的重试，没有可继续验证的 Session/CSRF；该分支只能在同源 Origin/Referer 与 Fetch Metadata 通过时清除认证及预认证 Cookie、返回 204，禁止读取身份或执行任何状态写。此例外只适用于 `logout`，不能推广到其他非安全方法。

## 影响与验证

同时使用 Origin/Referer 与 Fetch Metadata 纵深防御。测试覆盖首登、轮换、刷新、多标签、过期、无界重试阻断，以及有效 Session 登出必须带 CSRF、失效 Session 的同源登出只清 Cookie 且可重复。
