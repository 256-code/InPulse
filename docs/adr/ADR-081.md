# ADR-081：组织（部门）成员分组、批量归属与同组织可见

- 状态：Accepted（2026-10-16 接受，首批实现随本批落库）
- 日期：2026-10-16
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：新增迁移 `0046`；新增 6 条路由（119 → 125）；沿用 [ADR-013](ADR-013.md)（事务边界）、[ADR-019](ADR-019.md)（幂等默认）、[ADR-023](ADR-023.md)（allowlist 不变）、[ADR-029](ADR-029.md)（统一错误体与响应校验）、[ADR-031](ADR-031.md)（管理员门禁）；指派选择器的组织视图为第二批，不在本批。

## 1. 背景

用户需求要点：

> 要求在成员设置管理员可以建立组织或部门将成员分开，成员可以看同一组织的其他成员，然后指派成员的时候也可以选择一整个组织或组织里面选人
> 那你这种我安排拉取成员进入组织得一个一个拉了（→ 组织归属必须支持批量操作）

- 现状：系统没有组织 / 部门概念；「成员与设置」仅系统管理员可见，普通成员没有任何全局成员视图；任务指派只能从当前项目活跃成员里多选（1～20 人），且必须是项目成员。
- 已确认口径（与项目负责人对齐）：组织为全局平铺列表（不建多级部门树）；一名成员同一时间至多归属一个组织（可暂不分配）；批量归属必须支持（成员列表多选一键加入组织、组织面板多选拉人）；指派「一整个组织」为选择器层面的成员快照展开（第二批），不改变「负责人必须是项目活跃成员」的既有规则。

## 2. 决策

### 2.1 数据模型（迁移 0046）

- 新增 `app.organizations`：`id`（IDENTITY 主键）、`name`（1～100 字符，`btrim` 后非空）、`row_version`、`created_at`、`updated_at`；函数唯一索引 `organizations_name_key` 按 `lower(btrim(name))` 去重（同名不同大小写 / 前后空白视为冲突）。
- 新增 `app.users.organization_id`（可空整数，FK → `app.organizations(id)`，`ON DELETE SET NULL`）：一名成员至多归属一个组织，未分配为 `NULL`；删除组织时成员自动回到未分配，不级联删除任何用户数据。
- 授权：`app_runtime` 对 `app.organizations` 具备 `SELECT / INSERT / UPDATE / DELETE`；`app_backup` 具备 `SELECT`。迁移内 `DO` 块校验属主、约束、函数索引与最小授权（与 0042 同款 fail closed）。
- 组织是配置维度、非业务历史：删除即物理删除（成员归属清空 + 审计留痕），不做软删除与还原；成员的组织归属支持随时调整。

### 2.2 六条路由（119 → 125）

- `GET /api/v1/admin/organizations`（`listOrganizations`）：完整管理员 Session；返回全部组织（id / name / rowVersion / createdAt / updatedAt），按 id 升序；响应 `no-store`；无 CSRF 与幂等。
- `POST /api/v1/admin/organizations`（`createOrganization`）：完整管理员 Session；`{ name }`；CSRF + `Idempotency-Key`（契约 1.0.0）；重名 409 `ORGANIZATION_NAME_CONFLICT`；写审计 `admin.organization.create`。
- `PATCH /api/v1/admin/organizations/{organizationId}`（`updateOrganization`）：整笔替换 `name`；CSRF + `Idempotency-Key` + `If-Match`；404 `ORGANIZATION_NOT_FOUND`；409 `ORGANIZATION_VERSION_CONFLICT` / `ORGANIZATION_NAME_CONFLICT`；审计 `admin.organization.update`。
- `DELETE /api/v1/admin/organizations/{organizationId}`（`deleteOrganization`）：`If-Match`；204 无 body；成员自动变未分配；审计 `admin.organization.delete`（含成员数）。
- `POST /api/v1/admin/users/organization`（`assignUsersOrganization`）：`{ userIds: 1～200 去重, organizationId: 正整数或 null }`；CSRF + `Idempotency-Key`；按用户 ID 升序 `FOR UPDATE` 逐行切换归属（`row_version + 1`）；组织不存在 422 `ORGANIZATION_NOT_FOUND`；返回 `{ updatedCount }`（真正变化行数，重复调用为 0）；审计 `admin.user.organizations.assign`。
- `GET /api/v1/organizations/me/members`（`getMyOrganizationMembers`）：任意有效会话；返回当前用户所属组织（或 null）与该组织 ACTIVE 成员（`id / name / avatarUrl / isAdmin`，最多 300 条，与 `getUserDirectory` 同脱敏口径）；未分配返回空列表；响应 `no-store`；无 CSRF 与幂等。
- 三条 admin 写路由的幂等重放授权策略为 `actorOnly`（复核当前有效的完整管理员会话）：组织结果可能在重放前被后续操作改名 / 删除（ADR-062 对 `deleteProject` 的同一取舍），资源级复核会把合法重放变成 404。
- 汇总「组织成员数」由前端从 `listAdminUsers` 结果聚合，不新增接口。

### 2.3 前端（第一批）

- 「成员与设置」入口对全体成员开放（侧栏去掉 `adminOnly`）：普通成员打开 `/settings` 时只渲染只读的「成员与角色」视图（自己所属组织 + 同组织成员，脱敏字段；未分配时说明原因），看不到任何管理操作与组织管理；管理员视图保持全量列表与全部管理能力。
- 管理员「成员与角色」增强：成员行显示所属组织；列表默认保持纯浏览（不显示任何勾选框），点「批量管理」按钮后才进入批量模式——显示勾选框、全选当前搜索结果、加入组织 / 移出组织 / 清空选择 / 退出批量；成员列表按组织分组显示（当前账号所在组织置顶、其余按组织 id 升序、未分配最后，组标题显示组织名与人数，组内保持账户列表原有顺序）；新增「组织管理」弹窗——新建、改名、删除（删除二次确认并提示「N 名成员将变为未分配」）、每个组织的成员数与成员一览（可在组织内直接批量拉人）。
- 指派选择器的组织视图（任务创建与改派的「一键选中整个组织」）为第二批。

> 2026-10-16 修订（用户反馈）：批量操作不默认显示勾选框、需点「批量管理」显式进入；成员列表按组织分组，相同部门成员放在一块。

> 2026-10-16 修订（第二批部分落地 + 入口修正）：① 指派选择器的组织视图先落地在「新建项目」表单的「初始项目成员」选择器——`getUserDirectory` 返回 `organizationId` / `organizationName`（可空），下拉按组织分组，组织按钮支持「全选 / 取消全选整个组织」（展开为成员快照并裁剪到 1～20 人上限）；任务创建 / 改派选择器的同类能力仍待落地。② 修正 `/settings` 路由守卫：首批「入口对全体成员开放」只改了侧栏，路由仍带 `requiresAdmin`，普通成员被「无权访问」拦截；已改为 `requiresAuth`，普通成员进入后只渲染只读同组织视图，浏览器 E2E 用例同步改为验证只读视图。

### 2.4 权限与安全

- 组织管理（建 / 改 / 删 / 批量归属）为系统管理员专属；沿用 ADR-031：只要求当前有效的完整管理员 Session（不要求 TOTP 重认证）。
- 批量归属按用户 ID 升序显式行锁、单事务完成；`userIds` 去重、数量 1～200；组织名与长度在服务端校验，唯一冲突映射 409。
- 同组织可见是本批新增的只读可见面：只暴露当前用户自己组织内的 ACTIVE 成员与脱敏字段（不返回登录名、邮箱、停用状态与管理材料）；不改变 `getUserDirectory` 既有全量目录口径，也不放宽任何既有授权。
- 组织数据不含敏感信息；不引入新 Secret、新依赖与新环境变量。

## 3. 审计与一致性

- 组织 CRUD 与批量归属全部走既有审计链（同事务），事件为 `admin.organization.create` / `admin.organization.update` / `admin.organization.delete` / `admin.user.organizations.assign`；批量归属审计记录 `organizationId / userIds / updatedCount`，删除组织审计只记录成员数、不记录成员明细。
- 批量归属只更新 `organization_id IS DISTINCT FROM` 目标值的行，因此重复调用自然幂等（`updatedCount = 0`），版本不无谓增长。
- 数据库约束是最终防线：`organization_id` FK、名称函数唯一索引、长度与 `row_version` CHECK。

## 4. 非目标与后续批次

- 不做：一人多组织、多级部门树、组织排序自定义、组织批量入项目 / 自动入项目、企业微信通讯录同步、组织维度的权限继承（组织不代表项目权限）。
- 第二批：选择器的组织视图——`listActiveProjectMembers` 增加组织字段，选择器按组织分组并提供「选中整个组织」（展开为当前项目内的组织成员快照，仍受 1～20 人与「负责人必须是项目活跃成员」的限制）。
  - 2026-10-16 进展：新建项目「初始项目成员」选择器已落地（在 `getUserDirectory` 返回的组织字段上分组与整组勾选，见 §2.3 修订）；任务创建 / 改派选择器仍待落地。
- 不改变 [ADR-040](ADR-040.md) 的指派规则与 [ADR-039](ADR-039.md) 的项目内角色下放清单。

## 5. 后果与验收

- 验收：`permissions:check` 125 / 125；`contract:validate` 125 条；真实 PostgreSQL 集成测试覆盖组织 CRUD（含重名 / 版本冲突 / 删除清空归属）、批量归属（含未分配、幂等重复、越权 403、未认证 401）、同组织可见（跨组织不可见、未分配空列表）与审计；Web 单测覆盖管理员批量操作、组织管理与普通成员只读视图；开发日志见本批条目与测试矩阵 ORGANIZATION 小节。
- 2026-10-16 第二批（部分）验收：用户目录组织字段（真实 PostgreSQL 集成 3 例，含未分配 `null`）、新建项目选择器分组与整组勾选（`CalmSelect` / `CreateProjectModal` Web 单测）、普通成员 `/settings` 入口放行（路由集成用例，E2E 用例改写为只读视图验证，尚未全量运行）。
- 后果：成员从此有稳定的组织维度，管理员可以按组织整理成员并批量操作；指派器的组织选择在第二批接入，两层互不阻塞。
