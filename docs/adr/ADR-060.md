# ADR-060 审计读取不写留痕：移除 `AUDIT_LOG_READ` 与 `readTrail`

- 状态：Accepted
- 日期：2026-10-09
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：替代 [ADR-042](ADR-042.md)（原始审计读取留痕按「查看」计数）；修订技术设计 §1.2 / §7.4 / §11 与系统设计 §3.8 / §6 的审计读取留痕表述；沿用 [ADR-008](ADR-008.md) 的审计只追加哈希链、[ADR-031](ADR-031.md) 的完整管理员 Session 门禁与 F-08 步骤 6 的远端 WORM 归档（`apps/ops`）

## 1. 背景

用户指示（原话）：

> 审计日志不需要记录读取留痕，把记录读取留痕去除掉，既然没用读取留痕了那也没必要隐藏

当前事实：

- [ADR-042](ADR-042.md) 把读取留痕从「每次请求」降噪为「每次查看」：进入审计页与切换审计对象（SYSTEM 链 ↔ 各 PROJECT 链）各写一条 `AUDIT_LOG_READ`，记录操作人、filters、returnedCount、hasMore 与请求元数据（不含审计正文）；同一次查看内的筛选、重置、重试与分页不写；留痕失败整体失败、不返回未留痕结果。
- 这使 `GET /api/v1/audit-logs` 事实上成为**写路由**：只读路径也要占用 `app_runtime` 的受限追加函数与 SYSTEM 链锁，读取失败面因此多出「留痕写失败即整体失败」一种。
- 留痕行进入不可变审计链后，读侧为了「看起来干净」引入了展示层机制（「隐藏读取留痕」勾选框、隐藏条数提示、空态「显示读取留痕」按钮），复杂度与信息价值倒挂：`AUDIT_LOG_READ` 是运维观察，不是业务事件，也不是安全事件。
- 读取取证的替代来源已经存在：远端 WORM 归档（F-08 步骤 6，`apps/ops` 每小时检查点、每日加密明细导出、对象锁 ≥30 天）与部署层访问日志；读取不需要在链内自证。

## 2. 决策

### 2.1 读取不写审计

1. `AuditQueryService` 删除留痕写入路径：不再接收 `UnitOfWork` / `AuditWritePort`，返回结果前不再向 SYSTEM 链追加 `AUDIT_LOG_READ`；「留痕失败整体失败」的语义随写入路径一并删除。
2. Route Registry 的 `getAuditLogs` 把 `auditAction` 改为 `none`（只读路由不再声明审计动作）；`authPolicy` 仍为 `adminSession`，CSRF / 幂等 / 版本 / 并发与 `securityFlow` 策略不变。
3. `audit_reader` 只读连接、`audit_writer` 角色与受限追加函数、审计链哈希与锁序、远端归档均不变；`app_runtime` 的授权面不变（本次只是不再调用追加函数）。

### 2.2 删除 `readTrail` 契约参数

`auditLogQueryRequestSchema` 删除 `readTrail`，`.strict()` 保留：旧客户端继续携带 `readTrail` 会在 Schema 层 422 `VALIDATION_FAILED`。这是破坏性契约变更（按 [AGENTS.md](../../AGENTS.md) §6 记录于本 ADR）；本路由本就是只读 GET，幂等与并发策略不受影响。无迁移、无新表、无新错误码。

### 2.3 历史留痕行保留并按普通行可读

1. 已写入的 `AUDIT_LOG_READ` 行不清理：审计链只追加（[ADR-008](ADR-008.md)），删除行会破坏哈希链；本决策不触碰数据库。
2. 前端删除全部「隐藏读取留痕」机制：勾选框、「本页已隐藏 N 条读取留痕」提示、空态「本页记录均为读取留痕」与「显示读取留痕」按钮；历史留痕行按普通审计行渲染（保留动作标签 `AUDIT_LOG_READ` → 「读取审计日志」，供历史行展示与动作筛选使用）。
3. 页头说明、项目动态快照弹窗与审计快照弹窗中「读取已留痕 / 读取本身已留痕」类文案一并删除；页头改为说明「读取不会在审计链留下记录」。

## 3. 影响与验证

- 读路径更简单：读取不再是写操作，不再占用 SYSTEM 链锁，也不再存在「留痕写失败 → 读取 500」的失败模式；`no-store`、签名游标、筛选与 422 语义不变。
- 审计页不再需要展示层过滤：历史留痕行可见、可筛（`action=AUDIT_LOG_READ` 仍可精确过滤）。
- 回归防线（改动该口径时必须同时跑）：
  - `apps/api/test/audit-logs.integration.test.ts`（8 例，真实 PostgreSQL）：读取 SYSTEM 链与 `PROJECT:<id>` 链、带签名游标分页与切换链后，链上 `AUDIT_LOG_READ` 行数不变；携带 `readTrail` 的请求 422 `VALIDATION_FAILED`；
  - `apps/web/src/features/audit/AuditLogPageView.test.tsx` 与 `audit-query.test.tsx`（19 例）：历史 `AUDIT_LOG_READ` 行按普通行渲染且可打开快照；页面不出现隐藏开关、隐藏条数与「显示读取留痕」；查询请求只带分页与筛选参数（无 `readTrail`）；
  - `apps/e2e/tests/audit.spec.ts`（2 例，真实浏览器）：普通成员 403；管理员以测试自建项目的 `PROJECT:<id>` 链为确定性锚点（`project.create`）验证筛选与快照，并断言页头「读取不会在审计链留下记录」且页面无隐藏读取留痕入口。
- E2E 锚点变化：读取不再写 SYSTEM 链后，SYSTEM 链在干净测试库中没有本测试产生的行，浏览器用例改以 `createProjectViaUi` 建立的 `PROJECT:<id>` 链取证（测试自身产生的确定性锚点），不依赖环境残留数据。

## 4. 非目标

- 不改审计链结构、HMAC、`key_version` 轮换、并发锁序与远端归档；不改 `audit_reader` 只读连接与配置缺失 fail closed；不改管理员 Session 门禁与 422 校验。
- 不为「读取取证」新增替代机制；将来若需要读取侧取证，必须新增 ADR 并同步权限矩阵与测试矩阵。
