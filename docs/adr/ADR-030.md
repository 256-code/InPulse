# ADR-030：空项目、业务模块编号与任务就地创建归属

- 状态：Accepted
- 决策日期：2026-09-14
- 接受依据：用户在本次任务中明确取消默认未分类模块、采用项目内业务编号、支持任务与新归属同时创建，并授权编码。
- 替代范围：功能设计 §8.3/§10.2、技术设计项目初始化中的自动未分类模块要求，以及聚合任务查询仅支持自指维度的既有裁决。保留 ADR-012 的创建者成员历史、ADR-013 的显式事务与 ADR-022 的类型化链接。

## 决策

1. 新项目可以没有模块；数据库不再强制存在一个未分类模块。创建者的初始成员历史仍强制保留，已有未分类模块不删除、不改变身份。
2. 模块业务编号为项目码-M-序号，每项目独立递增、不补零。内部 ID 与外键不变。使用现有 code_sequences 机制，模块 INSERT 触发器统一分配，兼容旧写入方；历史模块按项目和 ID 顺序补编号。编号不可修改。
3. 新建任务可选已有或自定义模块、功能；自定义是表单选项，不是默认模块名称。Workflow 经公开 CommandPort 在同一事务中创建归属、任务及审计/投影，整笔幂等，失败整笔回滚。联合创建先通过项目公开端口取得项目排他锁，再实时鉴权；既有写入先取得项目共享锁，因此不会在持有审计锁后再等待另一事务的编号序列。普通创建不得复用遗留转换通知语义。
4. 普通成员可读取同项目当前成员基本资料；管理员原成员管理和高风险操作规则不变。
5. 任务中心增加项目内全员任务和管理员跨项目任务视图；仍由服务端实时项目授权过滤。逾期筛选在 SQL 分页之前执行。
6. 功能增加可选验收标准，作为当前功能说明的一部分管理，不自动阻断任务完成。项目根仓库复用类型化外链关联，标记由部分唯一索引约束，runtime 只新增标记列的 UPDATE 权限，不远程抓取。

## 升级与验证

通过新增迁移修改约束，不改历史迁移；先迁移再部署配套 API/Web。旧版本恢复自动创建模块仍合法，但新项目不再能假定存在默认模块，回退时不得恢复旧的“恰好一个”约束。受影响写接口升级幂等契约版本，旧 Key 不能重放旧结构。验证创建者历史、历史模块、编号并发、联合事务回滚、实时权限和分页。
