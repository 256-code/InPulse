# ADR-027：契约生成链路使用 Zod 4 JSON Schema 与仓库内生成器

- 状态：Proposed
- 提出日期：2026-09-07
- 关联：[ADR-004](ADR-004.md)、[ADR-017](ADR-017.md)、[ADR-019](ADR-019.md)、[ADR-023](ADR-023.md)、[ADR-026](ADR-026.md)

## 背景

[ADR-004](ADR-004.md) 确定 Schema Registry/Zod 与 Route Registry 共同生成 OpenAPI 3.1 与 TypeScript 客户端，技术设计 §12.4 要求每个 PR 通过 OpenAPI/客户端漂移检查与 Route Registry/权限/响应 Schema 完整性检查。`AGENTS.md` 第 4 节把「OpenAPI 生成工具」列为阶段 0 尚未定案项，并禁止在规则或实现中伪装成已冻结选择。

阶段 0 需要真实落库这条链路才能执行上述门禁，因此必须先形成决策记录，而不是让实现默认成为既成事实。

## 决策

1. **JSON Schema 来源**：Schema Registry 的每个条目是 Zod 4（锁定 4.5.4）schema，OpenAPI `components.schemas` 由 Zod 内置 `z.toJSONSchema(..., { target: "draft-2020-12" })` 产出，不引入独立的 JSON Schema 定义源，避免出现第三份真相。
2. **生成器归属**：OpenAPI 文档与 TypeScript 客户端由仓库内生成器产出（`packages/api-contract/src/json-schema.ts`、`openapi.ts`、`ts-types.ts`、`client.ts`），入口为 `pnpm contract:generate`。本期不把 `@nestjs/swagger`、`openapi-generator`、`orval`、`openapi-typescript` 等第三方生成工具加入生产依赖。
3. **生成物落库与只读性**：`packages/api-contract/generated/openapi.json` 与 `apps/web/src/generated/api/{types,client,index}.ts` 提交入库，只能由生成器写入；`pnpm contract:drift` 逐字节比对生成结果与已提交内容，并拒绝生成目录中出现非生成器产出的文件。
4. **Route Registry 是唯一 HTTP 元数据来源**：`packages/api-contract/src/route-registry.ts` 登记 method、path、operationId、状态码、Content-Type、鉴权、CSRF、幂等与并发策略；不适用的策略必须显式写 `none`。`pnpm contract:validate` 校验策略完整性、`idempotencyReplayPolicy`/`replayAuthorizationPolicy` 的字段边界与 Secret 字段禁令（ADR-019/ADR-023），并静态扫描 `apps/api` Controller 绑定，要求每个已登记 operationId 恰好被一个 Controller 方法绑定。
5. **权限矩阵可执行化**：`packages/api-contract/src/permission-matrix.ts` 是 `docs/permissions.md` 的可执行副本；`pnpm permissions:check` 双向校验二者一致，并要求每条路由至少有一条允许与一条拒绝用例登记。
6. **契约指纹仅用于 CI**：`packages/api-contract/generated/route-contract-fingerprints.json` 记录每个 `idempotencyRequired` operationId 在某个幂等契约版本下的 SHA-256 指纹，只追加不重写，用于检测「契约已变更但未升级 `idempotencyContractVersion`」。它是 CI 侧变更探测器，**不是**运行时幂等 fingerprint；运行时仍必须使用带版本密钥的 HMAC-SHA-256（`AGENTS.md` 第 6 节）。
7. **本 ADR 不决定的事项**：Nest Zod Pipe/Serializer 组合与运行参数仍属 `AGENTS.md` 第 4 节未定案项；[ADR-026](ADR-026.md) 已说明本期使用自研 Zod Pipe 与序列化拦截器，其定案仍需独立评审。

## 影响与验证

- 状态为 `Proposed`：实现已按本草案落库以便执行 §12.4 门禁，但在人工评审转为 `Accepted` 前，不得把该组合当作已冻结基线，也不得据此拒绝评估第三方生成工具。
- 转为 `Accepted` 前必须完成的评审项：确认 Zod `z.toJSONSchema` 的 draft-2020-12 输出满足 OpenAPI 3.1 子集要求；确认自研 TS 类型打印器（`ts-types.ts`）在遇到不支持节点时抛错而非静默降级；确认生成客户端不引入裸 `fetch` 之外的传输依赖。
- 已实际执行的验证（2026-09-07，Windows / Node 24.20.0 / pnpm 11.19.0）：`pnpm contract:generate` 产出 5 个生成物；`pnpm contract:drift`、`pnpm contract:validate`（1 条路由）、`pnpm permissions:check`（1 条操作 / 1 条路由）与 `pnpm --filter @inpulse/api-contract test:unit`（3 个文件 50 个用例）全部通过；`pnpm lint`、`pnpm typecheck`、`pnpm build` 通过。
- 未实际执行的验证：`.github/workflows/ci.yml` 中的 GitHub Actions 运行本身（本机无 Actions 运行环境）。
- 若评审决定改用第三方生成工具，必须新增 ADR 替代本记录，并在同一 PR 中重新生成全部生成物、更新 `AGENTS.md` 第 4/5 节与本文件状态。
