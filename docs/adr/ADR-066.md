# ADR-066：文档导入支持选择文件（浏览器本地读取文本）

- 状态：Accepted
- 日期：2026-10-10
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-064](ADR-064.md) 2.9 节非目标第 1 条——从「不做 .md 文件上传（V1 只粘贴文本）」改为「支持浏览器本地读取 .md / .markdown / .txt 文件内容填入导入文本」；仍不引入 multipart 上传、服务端文件接收与附件存储。模板版本仍为 1，无路由 / 契约 / 权限 / 数据库改动（路由仍 106 条）。

## 1. 背景

用户指示（原话）：

> 那除了粘贴能不能做个直接上传文件导入的

- ADR-064 的 V1 只提供「粘贴文本」入口；用户让其它 AI 生成模板内容后需要先手动打开文件、全选复制、再粘贴到文本框，多一步且容易漏内容。
- ADR-064 非目标第 1 条「不做 .md 文件上传」的原意是**不引入 multipart、服务端文件接收与附件对象存储**（对应系统设计「本期不引入附件对象存储」的非目标）；它并不排斥「浏览器本地把文件读成文本」——后者不新增任何传输、存储或解析面，仍然走同一条 `document` 文本通道与预览 / 确认流程。

## 2. 决策

### 2.1 前端本地读取，不引入上传后端

- 弹窗 INPUT 阶段新增「选择文件」按钮与隐藏的 `<input type="file">`（`accept=".md,.markdown,.txt,text/markdown,text/plain"`）；
- 选中文件后由浏览器 `File.text()` 读取为 UTF-8 文本（前端剔除 BOM），直接填入导入文本框；用户可继续编辑，然后照常「预览 → 确认导入」；
- **不新增路由、不新增契约字段、不引入 multipart / 服务端文件接收 / 临时文件 / 附件存储**；服务端只看到与粘贴完全相同的 `document` 文本。

### 2.2 本地校验（读取前拦截，全部不发请求）

- 扩展名白名单：`.md` / `.markdown` / `.txt`（大小写不敏感），其余提示「只支持 .md、.markdown 或 .txt 文本文件。」；
- 文件字节上限 1 MiB（UTF-8 最坏 4 字节/字符，与 20 万字符正文上限配合做读取前第一道校验）；
- 读取后字符数超过 20 万（`DOCUMENT_IMPORT_MAX_TEXT_LENGTH`）提示精简；
- 读取失败提示「文件读取失败，请重试或直接把内容粘贴进来。」；
- 以上全部是**本地提前提示**，不改变服务端既有校验（解析、限额与 422 问题清单照旧）。

### 2.3 读取成功回执

- 文本框下方显示「已读取文件：xxx.md，内容已填入上方，可编辑后预览。」；再次手动编辑内容不撤销该提示；
- 同一文件可连续重复选择（每次读取前清空 input 值）。

### 2.4 非目标

1. 不做 multipart / 服务端文件接收 / 附件对象存储 / 临时目录（文件从不离开浏览器）；
2. 不做拖拽上传与多文件批量导入（多文档批量仍见 ADR-064 非目标）；
3. 不做文件内容自动预览（仍需用户点「预览」，保持两步确认）；
4. 不做非 UTF-8 编码探测（GBK 等文件需先转 UTF-8）。

## 3. 影响

- **前端**：`DocumentImportModal.tsx`（按钮 + 隐藏 input + `handleFileSelected` + 提示）、`InpulseIcon.tsx` 新增 `upload` 图标、`design-system.css` 新增 `.import-file-hint`。
- **测试**：`DocumentImportModal.test.tsx` 新增 3 例（.md 读取与 BOM 剥离并预览、.pdf 拒绝、超 1 MiB 拒绝）；空内容提示文案改为「请粘贴内容或选择文件后再预览。」。
- **文档**：ADR-064 非目标第 1 条加修订提示；测试矩阵新增 `DOC-IMPORT-FILE-*`；三份设计文档与 AGENTS.md 同批更新。
