# ADR-025：V1 采用 PGroonga 实现 PostgreSQL 中文与标识符搜索

- 状态：Accepted
- 基线固化：2026-09-07
- 替代：ADR-010

## 背景

阶段 0 的 `pg_trgm` PoC 未满足参数化中文短查询默认使用 GIN 索引的门禁。
候选验证表明，PGroonga 的默认全文 opclass 在 V1 搜索范围内满足中文短词、
完整英文缩写、完整代码标识符和完整编号搜索，并能在 101000 行仿真数据上
使用 PGroonga 索引。

## 决策

V1 搜索仅要求支持中文短词、完整英文缩写、完整代码标识符和完整编号，
不将任意英文/代码子串搜索作为 V1 门禁，也不提供正则表达式搜索。

经 PoC 验证，默认 `pgroonga_text_full_text_search_ops_v2` 在 9 组 V1
语义探针中全部通过，90 条冻结金标 Recall@20 为 100%，跨项目隔离、特殊
输入和边界输入均通过。

因此，V1 采用 PGroonga 作为搜索索引实现，普通搜索使用：

```sql
normalized_search_text &@~ app.pgroonga_query_escape($1)
```

正式迁移中的索引应使用经评审的 schema 限定与回滚验证，示例为：

```sql
CREATE EXTENSION pgroonga;
CREATE INDEX idx_search_projection_pgroonga
  ON search_projection USING pgroonga (normalized_search_text);
```

该写法的默认 opclass 为 `pgroonga_text_full_text_search_ops_v2`；不得直接
照抄实验 SQL，必须在 PostgreSQL 18.6 官方基线验证后再固化。

V1 不采用未转义的正则查询 `&~`，不使用自定义 TokenNgram 或
TokenBigramSplitSymbolAlphaDigit 作为正式门禁方案。

如果 V2 要求任意英文/代码子串搜索，再单独评估 TokenNgram、
TokenBigramSplitSymbolAlphaDigit 或独立搜索引擎，不影响 V1 决策。

## 影响与验证

- PoC 使用 `groonga/pgroonga:4.0.8-alpine-18` 内置 PostgreSQL 18.4；生产
  必须证明 PostgreSQL 18.6 官方镜像中的 PGroonga 构建、扩展安装和索引可用。
- 正式迁移必须包含 `CREATE EXTENSION pgroonga`、SearchProjection 的
  PGroonga 索引定义，以及可审计的迁移与回滚验证。
- 所有普通搜索输入必须经过 `app.pgroonga_query_escape()`；禁止直接使用
  未转义 `&~` 或透传 Groonga 高级查询语法。
- 默认 `enable_seqscan = on` 下必须使用参数化查询和 PGroonga 索引；
  `enable_seqscan = off` 只能作为诊断手段，不能作为生产配置。
- 备份恢复后必须验证扩展、索引和查询可用；索引大小通过
  `pgroonga_command('object_inspect')` 检查。
