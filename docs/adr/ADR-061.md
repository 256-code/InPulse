# ADR-061 原始审计读取「全部记录（所有链）」与已下线动作码候选清理

- 状态：Accepted
- 日期：2026-10-09
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：扩展 [ADR-060](ADR-060.md) 的只读审计读取（读取不写留痕、路由策略不变）、[ADR-008](ADR-008.md) 的审计只追加哈希链、[ADR-031](ADR-031.md) 的完整管理员 Session 门禁；动作码下线的依据为 [ADR-043](ADR-043.md) / [ADR-044](ADR-044.md) / [ADR-045](ADR-045.md) / [ADR-054](ADR-054.md) / [ADR-060](ADR-060.md)

## 1. 背景

用户指示（原话）：

> 将不会产生的去除掉，然后动态审计加一个有全部记录的，以后默认就是这个

澄清后（用户二选一）确定为：**审计链下拉新增「全部记录（所有链）」并设为默认**，即跨链读取，而不是在客户端把各链结果拼起来。

当前事实：

- `GET /api/v1/audit-logs` 的读取范围是二选一：不传 `projectId` 读 `SYSTEM` 链，传 `projectId=N` 读 `PROJECT:<N>` 链，`ORDER BY sequence_no DESC` 单链分页。管理员要看全量活动必须逐链切换，`app.audit_logs` 里跨链的时间顺序没有读取入口。
- 各链 `sequence_no` 互相独立，**不能**用单个序号跨链定位，因此跨链分页必须换排序键与游标坐标；`app.audit_logs` 原有索引（主键 `(chain_id, sequence_no)`、`audit_logs_chain_prev_hash_unique`、`audit_logs_project_time_idx`、`audit_logs_actor_time_idx`）没有以 `occurred_at` 为前导键的索引，无法服务跨链 `ORDER BY occurred_at DESC`。
- 审计页「动作码」筛选候选来自前端 `ACTION_LABELS` 全量标签表，其中 11 个动作码已随各自 ADR 下线、**不会再产生**：`project.archive` / `project.archive.request` / `project.archive.reject`（ADR-043）、`module.archive` / `module.restore`（ADR-044）、`feature.archive` / `feature.restore`（ADR-045）、`task.archive` / `task.unarchive`（ADR-054）、`AUDIT_LOG_READ`（ADR-060）、`SYSTEM_TEST`（仅测试写入）；另有前缀族 `AUDIT_SEED_*`（仅演示种子数据）。历史行仍在链中，标签不能删。

## 2. 决策

### 2.1 读取范围三选一：新增 `chain=all` 跨链读取

1. `auditLogQueryRequestSchema` 新增可选字段 `chain: z.enum(["all"]).optional()`（`packages/api-contract`）。**缺省语义完全不变**：不传 `chain` 且不传 `projectId` 仍读 `SYSTEM` 链、仍按链内序号倒序分页。
2. 传 `chain=all` 时读取**全部链**（`SYSTEM` 与所有 `PROJECT:*`），`ORDER BY occurred_at DESC, chain_id DESC, sequence_no DESC` 做键集分页；同一 `occurred_at` 的行按 `chain_id` 与链内序号定序，保证跨页稳定、不重不漏。
3. `chain` 与 `projectId` **互斥**：同时传入返回 422 `VALIDATION_FAILED`（`details.reason = "invalid-chain"`）；`chain` 只接受 `"all"`，其余取值在 Schema 层 422。
4. 只读、不分页上限、`from` / `to` / `action` / `actorIds` 过滤与 `no-store` 语义与单链读取完全一致；跨链读取不新增写路径（[ADR-060](ADR-060.md) 后读取本就不写留痕）。

### 2.2 游标加链坐标（成对出现）

1. `AuditCursorPayload` 新增可选 `c`（`chain_id`）与 `t`（`occurred_at`，UTC ISO 毫秒/微秒精度）：跨链分页的位置由「时间 + 链 + 链内序号」三段构成，缺一段无法定位。
2. 两个字段**必须成对**出现：只出现其一的载荷视为 `malformed`，`encode` 时也同样成对校验（编程错误直接抛错，不静默降级）。
3. 单链读取的位置仍只用 `sequenceNo`，`c` / `t` 缺省即为 `null`；跨链分页若拿到的位置缺少链坐标（例如把单链游标拿到 `chain=all` 下继续翻页），返回 422 `invalid-cursor`，不猜测、不回退到首页。
4. 游标签名域仍为 `inpulse.audit-cursor.v1:`——链坐标是**新增可选字段**，未改变既有字段语义；旧游标在新增的跨链分支下按「坐标缺失」被拒绝，见第 3 条。
5. `AuditCursorService.decode` 的返回类型由 `number` 改为 `AuditCursorPosition | null`：无游标返回 `null`（不再是哨兵值 `0`），调用方按位置对象传参。

### 2.3 迁移 `0037`：跨链排序索引

- 迁移 `database/migrations/0037_audit_logs_cross_chain_idx.sql` 新增 `CREATE INDEX audit_logs_occurred_at_chain_seq_idx ON app.audit_logs (occurred_at DESC, chain_id DESC, sequence_no DESC);`，列序与排序键逐列一致（`⚠ 人工复核项` 已写入迁移注释）。
- 只加索引、不改表结构与既有索引：单链读取继续走主键反向扫描，跨链读取走新索引的 Index Only Scan（见 §3 的 `EXPLAIN` 证据）。

### 2.4 前端：默认「全部记录（所有链）」

1. `AuditChain` 类型扩展为三态：`{ kind: "all" }` / `{ kind: "system" }` / `{ kind: "project"; projectId: number }`；初始状态为 `{ kind: "all" }`，即**进入审计页默认跨链读取**。
2. 审计链下拉首项为「全部记录（所有链）」，其后是「SYSTEM 链（系统级）」与各项目链；页头「当前链」徽章与筛选指纹同步三态（`chain.kind === "all"` 时不传 `projectId`、改传 `chain=all`）。
3. 游标与查询指纹仍由服务端签发并绑定操作者与筛选，切换链即换指纹，旧游标 422 后前端回退首页（既有行为）。

### 2.5 动作码候选去除已下线动作码

1. 前端新增 `RETIRED_ACTION_CODES`（11 个死码的只读集合），`AUDIT_ACTION_OPTIONS` = `ACTION_LABELS` **过滤**后的候选列表（按中文标签排序）；`ACTION_LABELS` 与 `ACTION_PREFIX_LABELS` **原样保留**，历史行与快照仍按中文渲染（[ADR-060](ADR-060.md) §2.3 的同一口径）。
2. 动作码候选只影响筛选下拉的可选项；手动构造的 `action` 参数与历史行渲染不受影响（服务端不校验动作码取值域）。
3. 前缀族 `AUDIT_SEED_*` 不进候选（本就不在 `ACTION_LABELS` 中），历史行继续由 `ACTION_PREFIX_LABELS` 渲染为「演示种子数据」。

### 2.6 权限面不变

- `getAuditLogs` 仍为 `adminSession`（当前有效的完整管理员 Session，`is_admin`），CSRF / 幂等 / 版本 / 并发策略全 `none`（只读）。
- 跨链读取等价于「管理员在一次请求里读他本就有权读的全部链」，**不新增授权、不新增角色、不改错误码除 §2.1 的 422 细分以外**；非管理员仍是 401 / 403，与 [ADR-060](ADR-060.md) 一致。
- 路由总数不变（仍 105 条），无新增 / 删除路由，`docs/permissions.md` 只补说明性文字。

## 3. 影响与验证

- 管理员获得单入口全量视图：`chain=all` 首页即按发生时间倒序跨链返回，翻页由复合键集谓词保证「只向更早追加」；`projectId` 与 `chain=all` 互斥使读取模式没有隐式组合。
- 性能：`EXPLAIN (ANALYZE, BUFFERS)`（本地演示库 `app`，`app.audit_logs` 1,324 行）：
  - 跨链首页（`chain=all`，`limit=50`）：`Limit (actual time=0.055..0.102 rows=51.00)` → `Index Only Scan using audit_logs_occurred_at_chain_seq_idx on audit_logs (actual time=0.054..0.098 rows=51.00)`，`Heap Fetches: 51`，`Execution Time: 0.135 ms`，**无 Sort 节点**；
  - 单链（`SYSTEM`，`limit=50`）：`Index Only Scan Backward using audit_logs_pk on audit_logs`（`Index Cond: (chain_id = 'SYSTEM'::text)`），`Execution Time: 0.101 ms`，未受新索引影响。
- 回归防线（改动该口径时必须同时跑）：
  - `apps/api/test/audit-logs.integration.test.ts`（10 例，真实 PostgreSQL）：跨链并列时间排序稳定且分页不重不漏（4 行同 `occurred_at` 夹具，两次 `limit=2` 翻页后拼接等于首页顺序、去重后长度不变、末页 `hasMore false` / `nextCursor null`）；缺省仍只读 `SYSTEM` 链；`projectId` 仍只读项目链；`chain=all` 与 `projectId` 同传 422 `invalid-chain`；单链游标到跨链查询 422 `invalid-cursor`；读取不写链。
  - `apps/web/src/features/audit/AuditLogPageView.test.tsx` 与 `audit-query.test.tsx`（21 例）：默认读取「全部记录（所有链）」且首次请求为 `{ chain: "all", limit: 50 }`；切回 SYSTEM 链后请求不再携带 `chain`；动作候选不含 11 个死码而历史行仍按中文渲染。
  - `apps/e2e/tests/audit.spec.ts`（2 例，真实浏览器）：普通成员 403；管理员进入审计页即发 `chain=all` 请求且「当前链」为「全部记录（所有链）」，切到项目链后请求带 `projectId` 且不再带 `chain=all`，筛选、快照与「读取不留痕」断言不变。

## 4. 非目标

- 不新增 / 删除路由（Route Registry 仍 105 条），不改 `getAuditLogs` 的鉴权、CSRF、幂等与版本策略。
- 不改审计链结构、HMAC、`key_version` 轮换、并发锁序与远端 WORM 归档；不改 `audit_reader` 只读连接与配置缺失 fail closed。
- 不删除历史动作码行，也不把 `ACTION_LABELS` / `ACTION_PREFIX_LABELS` 的标签整表删除——两者是历史行的渲染依据。
- 不为非管理员开放跨链读取；不为「按链筛选」新增独立参数（`chain` 当前只接受 `"all"`）。
- 不改单链读取的默认语义：不传 `chain` 且不传 `projectId` 仍是 `SYSTEM` 链（默认跨链只存在于前端初始状态）。
