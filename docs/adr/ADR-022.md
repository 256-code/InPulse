# ADR-022：ExternalLinks 类型化关联模型

- 状态：Accepted
- 基线固化：2026-09-04

## 背景

多态外键或多个可空 owner 字段无法可靠保证同项目归属，并会制造链接重复。

## 决策

ExternalLinks 使用项目内链接实体与项目、任务、功能、记录的类型化关联表；复合外键保证关联对象属于同一项目，规范化 URL 上设置唯一约束并用 upsert 处理并发。

V1.1 只保存用户提交的 HTTPS GitHub 链接，不保存 GitHub Token，也不向链接发起网络请求。未来远程抓取能力必须新增 ADR 并完成 SSRF、凭据与配额设计。

## 影响与验证

测试覆盖 URL 规范化、非 HTTPS 拒绝、跨项目 FK 失败及并发去重。链接只作为引用展示，不代表远程内容可信。

## 修订（2026-10-08）

新增链接表单接受「项目根仓库下的裸 commit SHA」（`^[0-9a-fA-F]{7,64}$`，与 `external_sha` 的 CHECK 同形状）：由服务端在写入前用项目根仓库（`is_root_repository`）补全为 `https://github.com/<owner>/<repo>/commit/<sha>`，再走原有规范化与校验路径；未设置或无法解析根仓库时返回 422 `EXTERNAL_LINK_SHA_REQUIRES_ROOT_REPOSITORY`。决策本质不变：仍只保存 GitHub HTTPS 链接、不存 Token、不发网络请求，前端不拼 URL；因同一请求由必然 422 变为可成功写库，`addExternalLink` 的 `idempotencyContractVersion` 由 `2.0.0` 升到 `2.1.0`。

## 修订（2026-10-09）

项目视图改为读侧聚合：`listExternalLinks` 在 `targetType = PROJECT` 时返回「项目级关联 + 该项目任务 / 功能 / 已发布迭代记录上的关联」，按链接去重并附 `sources: [{ targetType, targetId, title }]`；其他目标仍只返回自身关联且不带 `sources`。

- 写入模型不变：仍只有类型化关联表与复合外键，每次关联仍是一行显式记录，不存在「关联任务即自动写入项目级关联」。
- 只聚合已发布记录：草稿属私域内容，已作废记录在搜索与统计口径上已对成员隐藏；管理员查看 VOID 来源需要另行设计（当前不提供）。
- 解除仍在来源入口：项目面板只对仍有项目级关联的条目提供「解除」（`canRemoveExternalLink`），聚合条目只标注来源，列表尾部提示到各自入口解除。
- 零数据库面、零新路由、零权限与幂等策略变化（Route Registry 仍 101 条）；`sources` 为可选字段，读路由非破坏性扩展。
- 回归防线：`apps/api/test/external-links.integration.test.ts`（四类来源聚合、同 URL 双来源顺序、跨项目排除、草稿 / 作废排除）与 `apps/web/src/features/external-links/ExternalLinksPanel.test.tsx`（来源标注与解除入口收敛）。

## 修订（2026-10-09）二

按用户指示（「取消任务以后项目那边链接要隐藏掉不显示」）收窄项目视图聚合的任务来源：任务分支只聚合**有效任务**（`lifecycle_status <> 'INVALID' AND work_status <> 'CANCELED'`），已取消与已无效任务上的链接不再出现在项目面板。

- 这是**读侧展示口径**，不是权限收窄或关联删除：`task_external_links` 关联行保留，任务自身面板（`targetType = TASK`）照常读取；把任务从已取消恢复为待办（`CANCELED -> TODO`）后链接重新出现在项目面板。
- 条件与仓库既有「有效任务」口径同一表达式（`apps/api/src/modules/tasks/task-query.port.ts` 的 `effectiveOnly`、`apps/api/src/stats/card-stat-columns.ts` 的 `effectiveTaskWhere`），没有新增独立口径；`TASK` 目标列表与其它读路径不变。
- 零数据库面、零新路由、零权限与幂等策略变化（Route Registry 仍 101 条）；`listExternalLinks` 的 summary 同步为「聚合其有效任务、功能与已发布记录上的关联」。
- 回归防线：`apps/api/test/external-links.integration.test.ts` 的「项目面板聚合排除已取消与无效任务上的链接，恢复后重新出现」（真实 PostgreSQL：`INVALID` 不进聚合、`CANCELED` 后消失、任务自身面板仍在、`task_external_links` 关联行保留、恢复为 `TODO` 后重新出现）。
