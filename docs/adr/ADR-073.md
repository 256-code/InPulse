# ADR-073：整项目导入时创建者默认算项目成员，并在草稿里显示为锁定标签

- 状态：Accepted（2026-10-14 接受，实现随本批落库）
- 日期：2026-10-14
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订并部分取代 [ADR-072](ADR-072.md)（删除 `MEMBER_CREATOR_MISSING`、取消「项目成员必须写创建者」、AI 提示词去掉 `creatorName`），补充 [ADR-064](ADR-064.md)（整项目导入的成员来源）与 [ADR-071](ADR-071.md)（工作台草稿）；沿用 [ADR-033](ADR-033.md)（创建者自动成为活跃成员并担任组长）、[ADR-065](ADR-065.md)（模板说明行）、[ADR-067](ADR-067.md) / [ADR-068](ADR-068.md)（AI 辅助口径）、[ADR-029](ADR-029.md)（统一错误体）。**无新增路由（仍 110 条）、无数据库迁移（仍 39 个）、无新增依赖、无权限变化**；契约模板常量文本有改动（生成物按 `pnpm contract:generate` 更新，`contract:drift` 无漂移），模板版本仍为 1。

## 1. 背景

用户本轮原话：

> 创建者名字不能直接写入固定吗？

ADR-072 把「项目成员名单必须含创建者本人」做成了 422：文档不写导入人就导入失败，用户被迫把导入人自己抄进名单；而工作台草稿里又完全看不到这件事（创建者由 ADR-033 在项目创建流程里自动入组并担任组长），用户在「点哪改哪」的左栏里既看不见、也猜不到服务端最终会加谁。同一件事实在文档、草稿、落库三处各说各话。

## 2. 决策

### 2.1 创建者由系统默认算成员，文档不用写

`apps/api/src/workflows/document-import.workflow.ts` 的 `NEW_PROJECT` 分支：

- 去掉「排除创建者」的过滤，创建者一律算进成员，且**排在第一位**；姓名经 `UserReadPort`（`users.listByIds`）在同一个事务里读，不额外起事务。
- 删除整条 `MEMBER_CREATOR_MISSING` 报错（被本条取代）。
- `MEMBER_REQUIRED` 文案改为「整项目导入必须用「- 项目成员：」列出成员（创建者默认就是成员，不用写），且必须包含全部任务负责人」；`MEMBER_LIMIT_EXCEEDED` 文案补「含创建者」。
- `memberIds` / `members` / `summary.memberAddCount` 口径统一为**含创建者**（与最终落库的成员行一致）；`ProjectBootstrapWorkflow` 内部的 `new Set([actorId, ...memberIds])` 负责去重，不产生重复成员行。

### 2.2 AI 提示词不再要求模型编创建者

`buildSystemPrompt(mode)` / `buildAiAssistMessages({ mode, text })` 去掉 `creatorName` 参数（ADR-072 §2.2 引入的那一个），整项目成员规则改为「所有任务的『负责人』都要写进去；创建者本人（本次导入的人，也就是提供这份文档的人）由系统默认算作项目成员，不要写进『- 项目成员：』」。三处文案保持同口径：契约模板说明行（`DOCUMENT_IMPORT_TEMPLATE`）、工作台「必填要素」、AI 提示词与右栏追问。

### 2.3 工作台：创建者在「项目成员」行上是一枚锁定标签

`apps/web/src/features/document-import/DocumentImportModal.tsx`：

- 只在整项目导入（模式 B）渲染：项目段「项目成员 / 成员」字段行上，在可编辑的名单值之前挂一枚 `.import-draft-tag.is-locked` 标签，内容是创建者**姓名** + 一枚锁图标，带 `title`「创建者默认就是成员，不能移除」；**没有删除按钮**，也不进入编辑态的可删标签行。
- **不改文档正文**：标签纯显示，`documentText` 一字不改，所以「预览文档」仍是一字不改的原版（ADR-071 的原文对照语义不被破坏，粘贴进来的原文也不会凭空多出一个人名）；成员行落库仍由服务端按 §2.1 负责。
- 前端覆盖检查同步：`checkDocumentMemberCoverage` 在负责人与创建者是同一账号时不算缺口（`DocumentMemberCoverageContext.creator`）。

### 2.4 与 ADR-072 的关系

ADR-072 的 `MEMBER_REQUIRED`（空名单）与 `ASSIGNEE_NOT_INITIAL_MEMBER`（负责人不在名单）保留；`MEMBER_CREATOR_MISSING` 整条被本条取代（见 §2.1）。两者判据都仍是**解析后的账号**而非字面。

## 3. 影响

- 文档作者不必再把导入人抄进名单；工作台左栏一眼看得见「创建者是谁、为什么删不掉」。
- 成员行由服务端插入创建者，与 ADR-033 的组长语义一致（组长在项目创建流程里定，不由文档导入改写）。
- 兼容性：ADR-072 时代「故意不写创建者」的文档会 422，本 ADR 之后正常导入，导入后的成员集合多一个创建者——这是本 ADR 的目的，不是回归。

## 4. 验证

- Web 单元：`document-import` 4 文件 107 例（新增 3 例：锁定标签存在且没有删除按钮、文档正文一字不改、编辑态里创建者不是可删标签、模式 A 不渲染）；Web 全量 105 文件 834 例。
- API / 真实 PostgreSQL 集成 / Playwright E2E 的结果见开发日志第一百七十五条。

## 5. 本 ADR 未覆盖（已拍板但尚未实现，不得当成已实现能力）

- 负责人不在项目成员里时改为**就地软提示**（「加入项目成员」或「更换负责人」），不再由服务端 422 拦死。
- 文档完全没写成员时，按任务负责人**汇聚**结果写回草稿字段并显式提示这是汇聚出来的。
- 项目成员里删掉某人后，TA 名下的任务**就地**提示重新分配。
- 成员类字段**只按登录名解析**（姓名不再当账号用），并把 `loginName` 加进 `GET /api/v1/users` 与工作台候选（候选只显示登录名）。

以上四项将各自另立 ADR 并同步功能设计、权限矩阵与测试矩阵后再落库。


## 6. 修订：AI 草稿必须写出创建者本人（2026-10-14，第一百七十七条）

用户指示：

> 可以初始成员里模型把创建者（林雨妍）也写了，因为她同时是任务负责人；UI 没有重复挂锁定标签。提示词可以说得更准：「创建者不是任何任务负责人」时也要写。

本条**取代 §2.2 的口径**（「创建者由系统默认算成员、不要写进『- 项目成员：』」，并因此去掉 `creatorName`）：

- 草稿是用户核对名单的唯一可见面。创建者不写进草稿，左栏「项目成员」就只有文档里写的那几个人，用户会以为漏了人；把 TA 写出来才符合「点哪改哪」。
- 服务端 §2.1 的兜底行为（文档写不写创建者都放行、都会落库）**不变**。所以这是「让 AI 产出一份更完整的草稿」，不是把校验重新变成必填。

落地口径：

- `ai-assist.prompt.ts` 重新接入可选 `creatorName`（`buildAiAssistMessages` / `buildSystemPrompt` / `modeRules`），整项目规则新增 `creatorRule(creatorName)`：创建者必须写进「- 项目成员：」，**与 TA 是不是任务负责人无关**；姓名由服务端从当前 Session 读出后注入（`document-import-http.service.ts` 的 `resolveCreatorName`，短只读事务、只进 system message、不写日志、不落库）；读不到姓名时不写死，只要求「本次导入人的姓名未知，不要编造姓名」——名单里的名字对不上账号会被预览拒绝，写错比不写更糟。
- 三处用户可见文案同口径：契约模板说明行（`DOCUMENT_IMPORT_TEMPLATE`）、工作台「必填要素」、`MEMBER_REQUIRED` 文案均为「须包含创建者本人与全部任务负责人」。
- §2.3 的锁定标签与第一百七十六条的 `memberValueHasCreator` 去重**保留**：草稿里写了创建者就不再重复挂标签。

未变更：§2.1、§2.4 与 §5 全部维持原样。验证结果见开发日志第一百七十七条。
