# ADR-079：未绑定企业微信的提醒弹窗（忽略 / 不再提醒）与绑定状态的机器人可用标记

- 状态：Accepted（2026-10-15 接受，实现随本批落库）
- 日期：2026-10-15
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：扩展 [ADR-069](ADR-069.md) §2.1（`WecomBindingStatus` 响应新增 `robotConfigured`）；沿用 [ADR-004](ADR-004.md)（契约生成）、[ADR-029](ADR-029.md)（统一错误体与响应校验）；无新增路由（119 条不变）、无迁移。

## 1. 背景

用户需求要点：

> 然后还需要如果用户没绑定会有一个弹窗提示用户绑定。然后用户可以选择跳转绑定，忽略，不再提醒

- ADR-069 的绑定入口此前只藏在「账户菜单 → 绑定企业微信」里：用户没有绑定时不会有任何提醒，容易一直错过任务指派的企微推送（阶段二投递）。
- 提醒不能打扰不该被打扰的人：管理员尚未配置机器人时（`app.wecom_robot_config` 无行），绑定本身不可用，此时提示「去绑定」只会把用户引到一个无法完成的流程。
- 个人绑定状态 `GET /me/wecom-binding` 此前不回传「机器人是否已配置」，前端无法区分「用户未绑定」与「机器人根本未配置」。

## 2. 决策

### 2.1 绑定状态新增 `robotConfigured`（扩展 ADR-069）

- `GET /api/v1/me/wecom-binding` 的响应 `WecomBindingStatus` 新增必填布尔 `robotConfigured`：`app.wecom_robot_config` 单行配置是否存在。不判密钥可用性（那是管理员 GET 的 `ready` / `disabledReason` 语义），成员侧只要「管理员已配置」即可提示绑定。
- 新增字段为响应增项：无新路由（119 条不变）、无迁移、无权限矩阵变化；OpenAPI、路由指纹与生成客户端随 `pnpm contract:generate` 更新（6 产物）。

### 2.2 提醒弹窗与三个动作（前端本地行为）

- 触发条件（全部满足才弹）：已登录且不在退出流程；当前账号未被忽略 / 未被「不再提醒」；绑定状态已成功取回且无进行中请求（不吃账号切换后的缓存旧值）；`robotConfigured === true` 且 `state === "UNBOUND"`。
- 三个动作：
  - 跳转绑定：「去绑定」关闭提醒并打开既有 `WecomBindingModal`（与账户菜单同一弹窗，复用绑定码流程）；
  - 忽略：本次浏览器会话不再弹（sessionStorage 按用户 ID 记录，含刷新；关闭标签页后恢复提醒）；
  - 不再提醒：按用户 ID 持久记录（localStorage），跨刷新与重启浏览器不再弹；之后仍可从账户菜单手动绑定。
- 关闭（X / Esc / 点遮罩）按「忽略」处理；`PENDING`（已有待用码）、`BOUND`、机器人未配置或状态读取失败时一律静默不弹。
- 提醒状态只存浏览器本地：不入库、不进契约、不写审计、不跨设备同步（已知取舍）；管理员与普通成员同为「用户」统一适用。

## 3. 非目标

- 不做服务端「提醒已读」同步 / 跨设备一致；不做企微侧推送提醒、邮件等其它通道；不改变绑定码流程与解绑语义。
- 不在机器人未配置时提示绑定；成员侧不校验密钥可用性 / 长连接状态（不做 local 试解密、不发网络请求）。

## 4. 验证

- Web 单测 `WecomBindingPromptModal.test.tsx` 10 例：触发条件五态（UNBOUND 且机器人已配置才弹；`robotConfigured=false` / BOUND / PENDING / 读取失败都不弹）、三动作与本地存储语义（忽略写 sessionStorage、不再提醒写 localStorage、去绑定回调且按忽略处理）、未登录 / 未取到账号不请求、已忽略 / 已不再提醒不请求。
- `AppLayout.test.tsx` 新增 2 例：未绑定且机器人已配置时弹出提醒、点「去绑定」打开绑定弹窗（会话标记写入 sessionStorage）；「不再提醒」按账号持久后重新挂载不弹也不请求；基础 mock 增补 `getWecomBinding`，`renderLayout` 按仓库测试约定加 `ConfigProvider`（`motion: false`）。
- API 集成 `wecom-binding.integration.test.ts` 15 例：UNBOUND 精确响应体新增 `robotConfigured: false`；机器人链接用例断言 `robotConfigured` 随配置行从 false 变 true（配置行经 bootstrap 连接确定性清空，避免共享单行状态受用例顺序影响）。
- 契约：`contract:generate`（6 产物）、`contract:drift` 无漂移、`contract:validate` 119 条、`permissions:check` 119 / 119、`check:frontend:boundaries`（363 模块）通过；Web 单测 112 文件 907 例、API 单测 79 文件 508 例、契约单测 102 例通过；完整门禁见开发日志。
- 未运行：Playwright E2E（`app_ci` 未配置机器人，提醒不会出现，不影响既有用例；本批未跑）、GitHub Actions（`test` 分支不触发）。

## 5. 影响

- 契约 `WecomBindingStatus` 增字段并重生成产物；前端新增提醒弹窗（`WecomBindingPromptModal`）与本地忽略状态模块（`wecom-binding-prompt.ts`）；无路由 / 迁移 / 权限变化。
- 未绑定成员登录后会看到一次绑定提醒；「忽略」下次会话再提醒、「不再提醒」永久关闭，两者都随时可从账户菜单手动绑定。
