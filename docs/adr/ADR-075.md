# ADR-075：空库首个 SSO 登录账号自动成为系统管理员

- 状态：Accepted（2026-10-15 接受，实现随本批落库）
- 日期：2026-10-15
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-032](ADR-032.md) 决策 5 的 JIT 默认权限（原「JIT 开通 `is_admin=false`」改为「平台已有账号时 `is_admin=false`；空库首个账号 `is_admin=true`」）；沿用 [ADR-031](ADR-031.md)（管理员高风险门禁只要求完整管理员 Session）与 [ADR-033](ADR-033.md)（项目内角色）。Casdoor 映射、会话、审计链、限流与路由均不变。**无新增路由、无数据库迁移、无新增依赖、无权限矩阵变化**；改动 `apps/api/src/auth/sso/sso-user.repository.ts`、`apps/api/src/auth/sso/sso-login.service.ts`（审计 payload）与对应测试。

## 1. 背景

SSO 上线后账号全部由 JIT 开通，且 ADR-032 定下的默认权限是「非管理员、无项目权限」。空库首次部署时（生产或全新测试环境）平台里没有任何管理员，而用户管理、成员管理、记录作废/恢复、原始审计等入口都要求 `is_admin`；文档里「首个系统管理员由一次性离线 bootstrap 命令创建」没有对应的仓库内实现，实际形成「首管理员真空」：所有人都能登录，但没人能授予任何人管理员权限。

用户 2026-10-15 原话：

> 现在情况是单点登录进去以后平台才会生成账户，但是都没有管理员权限，我现在希望如果平台里面没有账户那么第一个登录账户的人就是管理员

## 2. 决策

### 2.1 判定口径：以 `app.users` 是否存在行为准

SSO JIT 开通新账号的事务内执行 `NOT EXISTS (SELECT 1 FROM app.users)`：成立时新账号 `is_admin=true`，否则维持 `is_admin=false`。存在行即非空——包含停用（DISABLED）账号；首个账号之后无论其是否被停用都不再自动授予管理员，避免「停用首账号后任意下一个登录者成为管理员」。已绑定 / 已存在映射（`sso_subject` 命中、登录名绑定）的路径不受影响。

### 2.2 并发唯一性：事务级 advisory lock

「判定为空 -> INSERT」必须在同一事务内先用固定键的 `pg_advisory_xact_lock` 串行化：并发两个首登事务只有先提交的那个成为管理员，后到者在锁释放后重新判定并得到 `is_admin=false`。不依赖进程内锁、前端禁用或数据库外状态；首登事务回滚时锁随之释放，名额留给下一个登录者。

### 2.3 审计

`auth.sso_account_provisioned` 的 payload 增加 `grantedAdmin: true|false`，仅表达本次开通是否授予了首管理员。管理员身份不从 Casdoor 的任何 claim 读取（ADR-032 第 4 条不变）。

### 2.4 与口令登录的关系

本地口令入口在空库时不可用（没有账号可登录），因此首管理员只能来自 SSO JIT；口令登录路径不新增「首账号」语义。离线直接向数据库预置管理员的做法仍然可行且优先于 SSO 首登（预置后平台非空，SSO 不再授予）。

## 3. 影响与验证

- 首次部署：第一个完成 SSO 登录的人成为系统管理员；部署方应尽快核对该账号，若不符预期，可先按离线方式预置任一账号使 SSO 不再授予（或由预置管理员在用户管理中调整）。
- 安全：授予条件只看本地表状态，与 Casdoor 无关；并发窗口由数据库锁封闭；审计留痕（含 `grantedAdmin` 标记）。该管理员与用户管理授予的管理员完全同权，后续管理不受影响。
- 验证（真实 PostgreSQL + 桩 IdP）：空库首个账号 `is_admin=true` 且审计 `grantedAdmin=true`，第二个账号为 `false`；平台只有停用账号时不授予；两并发首登事务恰好一个管理员。测试在 cluster_bootstrap 新建的临时库上跑完整迁移（共享 app_ci 始终非空），见 `apps/api/test/sso-first-admin.integration.test.ts`。

## 4. 非目标

- 不把 Casdoor `isAdmin` 或任何外部 claim 映射到 `is_admin`。
- 不做「首位管理员白名单 / 邀请码 / 部署令牌」等变体；如未来需要更强的首次部署控制，另行 ADR。
- 不改变既有绑定、会话签发、限流与审计链机制。
