# ADR-033：项目内角色（组长与项目管理员）

- 状态：Accepted
- 基线固化：2026-09-16
- 取代/扩展：扩展 [ADR-012](ADR-012.md)（ADR-012 标记为 Superseded）。ADR-012 的「创建者不授予额外权限」被本决策限定为「创建行为本身不授予权限；组长身份由系统管理员显式任命产生，创建者只是默认候选」。成员关系仍是项目访问权的唯一来源这一点不变。

## 背景

业务要求项目创建者担任「项目小组组长」，可在**被赋予的项目内**添加/移除成员、归档/恢复模块（界口语「删除模块」按逻辑归档实现，不物理删除）、任命或撤销「项目管理员」；项目管理员可添加/移除成员与归档/恢复模块，但不能任命角色。此前系统只有系统管理员与项目成员两类角色，成员增删与模块归档/恢复均为系统管理员专属（权限矩阵 `addProjectMember` / `removeProjectMember` / `archiveModule` / `restoreModule`）。

## 决策

1. **角色模型**：`app.project_members` 新增 `role TEXT NOT NULL DEFAULT 'MEMBER'`，取值 `MEMBER | PROJECT_ADMIN | LEADER`，`CHECK` 约束固定枚举。角色只存在于成员行上：成员被移除（`status='REMOVED'`）即失去角色与全部项目内权限；重新加入一律从 `MEMBER` 开始。
2. **唯一性**：每个项目至多一条 `ACTIVE` 且 `role='LEADER'` 的成员行（部分唯一索引）；至多身份互斥由单列枚举天然保证。
3. **任命来源**：新建项目的创建者成员行以 `role='LEADER'` 落库（创建流程不可取消该成员关系，沿用 ADR-012 的创建不变量）；存量项目由迁移把 `projects.created_by` 对应的 `ACTIVE` 成员行回填为 `LEADER`（创建者已不在活跃成员时该项目无组长，须由系统管理员任命）。系统管理员可随时任命/转移/撤销组长与项目管理员；组长可任命/撤销**本项目**的项目管理员，但不能任命或撤销组长（含自己与他人的组长身份转移）。
4. **项目内权限**（仅在被赋予的项目内生效，跨项目一律 404/403 不变）：
   - `addProjectMember` / `removeProjectMember`：系统管理员、本项目 `LEADER`、本项目 `PROJECT_ADMIN` 允许；
   - `archiveModule` / `restoreModule`：同上三者允许（「删除模块」= 逻辑归档，不提供物理删除）；
   - `setProjectMemberRole`（新增路由）：系统管理员可设 `MEMBER | PROJECT_ADMIN | LEADER`；本项目 `LEADER` 只能设 `MEMBER | PROJECT_ADMIN`（即任命/撤销项目管理员），不得触碰任何 `LEADER` 行；
   - 其余路由鉴权不变。
5. **鉴权实现**：新增项目角色门禁服务（实时读取 `project_members.role`，不缓存进 Session）；受影响路由的 `authPolicy` 由 `adminSession` 调整为 `session`，角色条件作为业务授权登记在权限矩阵（`conditional` 条目）并由服务层在既有单事务内、取得项目级锁后校验；系统管理员经 `is_admin` 旁路。幂等重放前按既有 `replayAuthorizationPolicy` 重新验证当前认证与结果资源可读，并在重放授权器中追加「当前仍为系统管理员或具备该路由要求的项目角色」门禁。
6. **移除保护**：`removeProjectMember` 不得移除本项目 `LEADER` 成员行（含系统管理员操作），须先由系统管理员转移/撤销组长；防止项目失去唯一责任人。系统管理员自身不受成员关系影响（全局权限）。
7. **可见性**：成员列表响应携带 `role`；前端按角色显示操作入口（成员管理、模块归档/恢复、任命项目管理员）。

## 影响与验证

- 迁移：`0015_project_member_roles.sql`（列 + CHECK + 部分唯一索引 + 创建者回填 + `app_runtime` 权限不变，角色判定走既有成员读取路径）。
- 契约：`ProjectMemberRecordItem` 增 `role`；新增 `setProjectMemberRole` 路由（Session + CSRF + 数据库幂等，锁序 `["project"]`，并发控制沿用成员活跃唯一索引与状态检查，冲突 409）；`archiveModule` / `restoreModule` / `addProjectMember` / `removeProjectMember` / `listProjectMembers` / `listProjectMemberUnfinishedTasks` 的 `authPolicy` 由 `adminSession` 调整为 `session`，角色条件登记在权限矩阵 `conditional` 条目与 `docs/permissions.md`，服务层门禁与重放授权器同步追加角色校验。
- 审计动作：`project.member.role.set`；活动类型 `PROJECT_MEMBER_ROLE_CHANGED`。
- 测试：角色任命/撤销的越权矩阵（组长跨项目 404、PROJECT_ADMIN 任命角色 403、移除 LEADER 409、成员移除后角色失效）、模块归档的角色放行与跨项目拒绝、幂等重放的角色门禁，均须真实 PostgreSQL 集成覆盖。
