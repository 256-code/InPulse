# ADR-070：企业微信机器人凭据的管理员在线配置

- 状态：Accepted（2026-10-13 接受，实现随本批落库）
- 日期：2026-10-13
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-069](ADR-069.md) §2.4（投递凭证由桥接侧持有、不进入 InPulse 数据库）；沿用 [ADR-013](ADR-013.md)（事务边界）、[ADR-023](ADR-023.md)（幂等模式）、[ADR-029](ADR-029.md)（统一错误体与响应校验）；新增迁移 `0042`；新增 2 条管理员路由（113 → 115）。桥接侧读取解密与投递改造仍不在本批。2026-10-13 扩展：迁移 `0043` 为单行配置新增可空 `bot_profile_url`（机器人链接，展示到成员绑定弹窗），`updateWecomRobotConfig` 幂等契约 1.0.0 → 1.1.0。

## 1. 背景

用户需求要点：

> 给管理员一个口子页面管理机器人，然后填写需要的信息来更改机器人
> 如果后面更换机器人了需要有哪些更改

- 阶段一（ADR-069）解决「InPulse 账号 ↔ 企微 userid」绑定；机器人凭据（botId / secret）仍按 ADR-069 §2.4 由桥接进程本地持有：更换机器人必须登录服务器改桥接配置文件并重启，管理员在应用内既看不到当前配置是否可用，也无法自助更换。
- 用户明确要求：管理员在设置页填写 botId / secret 即可更换机器人；凭据不再由桥接侧手工维护，改为 InPulse 系统统一保管（密文落库）。

## 2. 决策

### 2.1 两条管理员路由（`/api/v1/admin/wecom-robot`）

- `GET /admin/wecom-robot`（`getWecomRobotConfig`）：返回配置视图（`configured` / `ready` / `disabledReason` / `botId` / `secretHint` / `secretKeyVersion` / `rowVersion` / `botProfileUrl` / `updatedAt` / `updatedByName`）；永不回显密钥明文或密文；只服务完整管理员 Session；`csrfPolicy: none`、`idempotencyPolicy: none`；响应 `no-store`。
- `PUT /admin/wecom-robot`（`updateWecomRobotConfig`）：`botId` 必填（1–128 字符、不含空白）；`secret` 可选（1–256 字符、不含空白；缺省或 `null` 表示保持已存密钥，首次配置必须提供）；`botProfileUrl` 可选（https、1–512；缺省保持现值、`null` 清空、字符串设置；2026-10-13 扩展，迁移 `0043`）；CSRF 必填 + 数据库级幂等（幂等契约 `1.1.0`，重放安全字段含 `botProfileUrl`，重放授权按「原始管理员 + 单行配置」重新校验）；写审计 `admin.wecomRobot.update`（before / after 摘要 + `secretChanged`，不含任何密钥材料）。
- 失败口径：主密钥不可用且请求需要加密新密钥时 503 `WECOM_ROBOT_CONFIG_KEY_UNAVAILABLE`（fail closed，不落明文、不回退环境变量）；字段校验失败 422；非管理员 403；无效 Session 401。
- 路由总数 113 → 115；两条路由都只服务完整管理员 Session（ADR-031 起不要求 TOTP 重认证）。

### 2.2 数据模型（迁移 0042）

- 单行表 `app.wecom_robot_config`（`id = 1` 单行约束）：`bot_id`、`secret_ciphertext`、`secret_key_version`、`secret_hint`（尾 4 位提示）、`updated_by`（FK `app.users`）、`updated_at`、`row_version`；迁移 `0043` 新增可空 `bot_profile_url`（https 前缀、长度 1–512，CHECK 兜底；非敏感展示字段）。
- 明文 Secret 永不入库、不写日志、不进审计、不进幂等物化：密文为 `nonce(12) || tag(16) || ciphertext`（AES-256-GCM），AAD 固定为常量 `app.wecom_robot_config.secret`。
- 配置行永不删除：`app_runtime` 只有 SELECT / INSERT / UPDATE（无 DELETE），`app_backup` 只读，迁移内 `DO $$` 部署断言兜底。

### 2.3 主密钥与 fail closed

- 主密钥只从 `/run/secrets/wecom_robot_encryption_key`（`WECOM_ROBOT_ENCRYPTION_KEY_FILE`）读取，`WECOM_ROBOT_ENCRYPTION_KEY_VERSION` 默认 1；文件必须位于 `/run/secrets/` 直接子项，仅 `NODE_ENV=test` 且显式设置 `WECOM_ROBOT_ENCRYPTION_KEY_TEST_PATH=1` 时允许临时路径（测试专用防线）。缺失 / 非法 / 版本缺失一律 fail closed，不回退明文环境变量。
- 同一份 keyring 文件同时供 InPulse API（加密保存与状态分类）与企业微信长连接桥接进程（读取 `bot_id`、解密 `secret`）使用；部署时两处挂载同一 Secret。
- GET 的可用状态分类：NOT_CONFIGURED（无配置行）/ ENCRYPTION_KEY_UNAVAILABLE（主密钥缺失或非法）/ CONFIG_INVALID（密文无法用当前 keyring 解密）；分类只做本地试解密，不发任何网络请求。

### 2.4 前端交互

- 「成员与设置」新增管理员页签「企业微信机器人」（`/settings?tab=wecomRobot`）：状态卡展示 ready / disabledReason / botId / 密钥尾号 / 机器人链接状态 / 最近保存人与时间；表单填写 botId、secret（密码框、永不回显、留空保持原密钥）与机器人链接（https、可空、留空清空）；保存先签发 CSRF 再携带一次性幂等 Key；所有请求经生成客户端。
- 成员「账户菜单 → 绑定企业微信」弹窗：绑定状态响应携带 `botProfileUrl`（2026-10-13 扩展）；管理员配置了机器人链接时，弹窗展示链接与「复制机器人链接」操作，指引成员在企业微信中打开机器人后再发送绑定码。

### 2.5 桥接侧接线（下一批，本批未实现）

- 本批只把「凭据可被管理员在线更换」落库为系统能力并开放管理页面；桥接进程改为从 `app.wecom_robot_config` 读取 `bot_id` 与解密后的 secret、以及配置变化后的重连策略，为下一批实现。桥接改造落地前，更换机器人仍须人工同步桥接本地配置。
- 不引入 Worker / Outbox / 定时任务；不把企微长连接移入 InPulse 进程。

## 3. 非目标

- 不改桥接进程代码；不做多机器人 / 多企业并存；不做密钥轮换专用 UI（keyring 版本字段已预留，轮换按新版本写入并通过重新保存生效）；不做配置历史页面（留痕以审计为准）。
- 不提供密钥读取 / 导出 / 下载；管理员只能覆盖保存，不能读回明文（连密文也不出库）。

## 5. 影响

- 路由 113 → 115；迁移新增 `0042`；权限矩阵新增 2 行。
- 修订 ADR-069 §2.4：投递凭证不再只由桥接侧持有，凭据密文进入 InPulse 数据库、由管理员在线维护；阶段二桥接投递改造（未实现）需按本 ADR 从数据库读取凭据。
- 管理员更换机器人（桥接接线落地后）不再需要登录服务器改配置文件；在此之前仍需人工同步桥接配置，不得把桥接改造描述为已交付。
