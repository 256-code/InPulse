# ADR-064：固定模板 Markdown 文档导入（项目内导入与整项目导入）

- 状态：Accepted
- 日期：2026-10-10
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：新增 F-32 能力；沿用 [ADR-004](ADR-004.md)（Schema Registry 与 Route Registry）、[ADR-013](ADR-013.md)（Workflow 与显式 UnitOfWork）、[ADR-029](ADR-029.md)（Contract 装饰器与统一错误体）、[ADR-039](ADR-039.md)（项目内管理操作对活跃成员开放）、[ADR-062](ADR-062.md)（项目物理删除会级联清空导入批次）；两条执行路由都走常规数据库级幂等，不进入 [ADR-023](ADR-023.md) 的 `securityFlow` 例外清单。
- 修订（2026-10-10）：2.1 节的行处理口径由 [ADR-065](ADR-065.md) 修订——以 `>` 开头的说明行与三个反引号 / `~~~` 代码围栏行不再报 `LINE_UNRECOGNIZED`，改为被解析器忽略；模板本体自带填写说明，弹窗新增「格式速查」。其余决策不变。
- 修订（2026-10-10，之二）：2.9 节非目标第 1 条由 [ADR-066](ADR-066.md) 修订——支持浏览器本地读取 `.md` / `.markdown` / `.txt` 文件内容填入导入文本；仍不做 multipart 上传、服务端文件接收与附件存储。

## 1. 背景

用户需求（原话归纳）：希望「通过导入固定的文档来直接将项目的模块功能任务那些建立好」，并与开发代理共同确认了以下口径：

1. 接受**固定 Markdown 模板**作为唯一输入格式；
2. 要能**导入整个项目**（文档里连项目段一起写，一次建立项目与全部下级）；
3. **负责人自动加入**项目成员；
4. **项目编码强制必填**；
5. 要**防止同一文档重复建**（重复导入必须被拒绝）；
6. 一份文档可以包含**多个模块与功能**；
7. 没填写的字段如果**不影响创建**就按默认值跳过（跳过字段，不跳过对象）。

导入后的模块、功能、任务必须与手工创建完全同构：同一套表、同一套编号（`code_sequences`）、同一套审计 / 活动 / 通知 / 搜索投影，不允许出现「导入专用」的旁路写法。

## 2. 决策

### 2.1 模板语法（模板版本 1）

只支持两种行：**标题行**与**字段行**；其余行 422 `LINE_UNRECOGNIZED`。

| 层级 | 标题 | 支持字段（`- 字段：值`，全角/半角冒号均可） |
|---|---|---|
| 一级 | `# 项目：名称` | `项目编码`（必填）、`项目说明`、`项目成员`（逗号分隔） |
| 二级 | `## 模块：名称` | `说明` |
| 三级 | `### 功能：名称` | `当前说明`、`验收标准`、`标签`（逗号分隔） |
| 四级 | `#### 任务：标题` | `负责人`（必填，逗号分隔）、`优先级`（普通/高/紧急，或 `NORMAL`/`HIGH`/`URGENT`）、`截止`（`YYYY-MM-DD`，按北京时间当日 23:59:59 落库）、`描述`、`影响功能`（仅模块级任务，逗号分隔） |

结构约束：

- 深度超过四级 422 `HEADING_TOO_DEEP`；标题层级与关键字不匹配 422 `HEADING_KIND_MISMATCH`；
- 未知字段、段落内重复字段、空文档、任务缺负责人一律 422（`UNKNOWN_FIELD` / `DUPLICATE_FIELD` / `EMPTY_DOCUMENT` / `ASSIGNEE_REQUIRED`）；
- 超长字段按各字段上限截断并回显问题（功能正文 50000 字符、说明 20000 字符、名称 200 / 500 字符等），超限对象按截断后创建；
- 规模上限：原文 200000 字符、模块 100、功能 500、任务 500、实体总量 1000、成员 300、单任务负责人 20、单功能标签 50；
- 模式 A（项目内导入）文档**不得**含项目段（422）；模式 B（整项目导入）文档**必须**含项目段（422）。

### 2.2 两种模式与四条路由

| 模式 | 预览（只读） | 执行（写） | 说明 |
|---|---|---|---|
| A 项目内导入 | `previewProjectDocumentImport` · `POST /api/v1/projects/{projectId}/document-imports/preview` | `importProjectDocument` · `POST /api/v1/projects/{projectId}/document-imports` | 导入到已有项目；项目可写门禁（活跃成员或系统管理员） |
| B 整项目导入 | `previewProjectImport` · `POST /api/v1/project-imports/preview` | `importProject` · `POST /api/v1/project-imports` | 任何已登录用户；在单事务内创建项目与全部下级 |

- 预览是纯校验接口：不写任何持久化状态，显式声明 `csrfPolicy: none`、`idempotencyPolicy: none`；执行是写命令：同源 / CSRF、数据库级幂等（`idempotencyContractVersion 1.0.0`）、`Idempotency-Key` 必填。
- 执行请求体带 `expectedDigest`（预览返回的摘要）：与执行时解析出的摘要不一致返回 409 `DOCUMENT_IMPORT_STALE`，防止「预览后改文档再执行」。
- 路由总数 102 → 106；不新增权限角色，权限沿用既有「项目可写」判定（模式 A）与「已登录」判定（模式 B）。
- 上下文规模上限为 1 MiB JSON（原文 200000 字符 UTF-8 最坏约 600 KiB），确保落在 API 与网关传输上限内。

### 2.3 复用与默认值（跳过字段，不跳过对象）

- **模块**：与项目内既有模块**名称精确匹配**（规范化后）时复用，不覆盖任何字段；匹配不一致的既有说明只发 WARNING `MODULE_REUSE_DIFFERS`。
- **功能**：与所属模块内既有功能同名时复用，不覆盖现有正文；差异只发 WARNING `FEATURE_REUSE_DIFFERS`。
- **任务**：一律新建（任务无「同名复用」语义）。
- 未填写字段按默认值创建：优先级 `NORMAL`、截止 `null`、描述 `""`、标签 `[]`、验收标准 `null`、影响功能 `[]`；缺省字段不产生 ERROR。
- 同一文档内同名模块 / 功能按**首次出现**解析，重复出现复用首次计划（不重复建）。

### 2.4 负责人与成员

- 负责人 / 项目成员令牌按**登录名或姓名**解析（规范化后）；未找到 422 `ASSIGNEE_UNRESOLVED` / `MEMBER_UNRESOLVED`，同名多人 422（需改用登录名）。
- **模式 B**：项目成员与全部任务负责人解析后**自动加入**新项目成员（去重、排除创建者），成员通知与项目创建同事务；成员总数超限 422。
- **模式 A**：负责人必须是目标项目的**当前活跃成员**，否则 422 `ASSIGNEE_NOT_MEMBER`（提示先加成员）；导入不隐式改变成员关系——避免普通成员借导入把任意用户拉进项目。

### 2.5 项目编码

- 模式 B 的 `项目编码` **强制必填**（不做「按名称派生」兜底），格式 `^[A-Z][A-Z0-9_]{1,31}$`；
- 预览返回 `codeAvailable`；已被占用时预览 `canApply=false`，执行返回 409 `PROJECT_CODE_CONFLICT`；
- 项目创建在同一事务内完成（复用 `ProjectBootstrapWorkflow`），编码唯一约束兜底并发。

### 2.6 查重：同一文档禁止重复导入

- 摘要 `digest` = 规范化文档文本（去 BOM、CRLF→LF）的 SHA-256 十六进制；
- **模式 A** 在目标项目内查重，**模式 B** 按摘要全局查重；
- 迁移 `0039` 新增 `app.document_import_runs`：每次成功执行写一行（摘要、模板版本、操作者、各层创建 / 复用计数，**不保存原文与解析正文**），`UNIQUE (project_id, document_digest)` 是最后防线；
- 预览返回既有批次（操作人、时间）并把 `canApply` 置 `false`；执行 409 `DOCUMENT_IMPORT_DUPLICATE`；并发下唯一约束冲突同样映射 409；
- 项目被物理删除（ADR-062）时 `app.purge_project` 一并清空该项目的批次行，同一文档可以重新导入到新项目。

### 2.7 事务、审计与投影

- 执行固定为**单个事务**：项目行锁（模式 A 对 `{projectId}`、模式 B 由项目创建 Workflow 锁）→ 权限 / 可写检查 → 摘要复核 → 重新解析与计划 → 按序创建（复用各域既有创建 Workflow / CommandPort）→ 写批次行 → 写审计 → 提交；
- 模块 / 功能 / 任务创建沿用各自的创建路径，因此活动、通知与搜索投影与手工创建完全一致，同事务写入；
- 额外写一条审计 `project.documentImport`（链归属：模式 A 为该项目链，模式 B 为新项目链），负载含摘要、模板版本与各层计数，不含文档原文；
- 任何 ERROR 问题导致整笔 422，**绝不部分落库**；幂等重放按资源引用 `documentImportReplayAuthorizer` 复核当前认证、项目与全部结果资源当前可读性；
- 数据库异常统一映射：行级问题 422 `DOCUMENT_IMPORT_INVALID`、重复 409、摘要过期 409、编码冲突 409 `PROJECT_CODE_CONFLICT`、并发名称冲突 409 `DOCUMENT_IMPORT_CONFLICT`、项目不可见 / 非成员 404 `PROJECT_NOT_FOUND`。

### 2.8 前端

- 项目列表页新增「从文档导入整项目」，模块页新增「从文档导入」（空项目在搭建引导头部同样给出入口）；
- 双阶段弹窗：粘贴模板（附「下载模板」）→ 预览（摘要 + 模块 / 功能 / 任务计划 + 行级问题清单 + 重复提示）→ 确认导入；
- 所有请求走生成客户端；执行前先签发 CSRF Token 并携带一次性 `Idempotency-Key`；错误按契约错误码映射为固定中文提示，服务端内部消息不下发。

### 2.9 非目标

1. 不做 `.md` 文件上传（V1 只粘贴文本，不引入 multipart 与附件存储）；**2026-10-10 由 [ADR-066](ADR-066.md) 修订：支持浏览器本地读取 `.md` / `.markdown` / `.txt` 文件内容填入导入文本，仍不做 multipart 上传、服务端文件接收与附件存储**；
2. 不支持自定义字段、YAML front matter、表格语法与文档导出；
3. 不把自由正文解析为业务字段：只有字段行进入系统，未识别行报错而不猜测；
4. 不为模式 B 增加管理员专属通道，也不新增数据库角色 / 权限；
5. 不改变 F-04 手工创建项目的「编码可缺省派生」语义——文档导入是显式必填的独立入口。
