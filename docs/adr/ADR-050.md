# ADR-050：项目删除记录的可见性

- 状态：Accepted
- 基线固化：2026-09-28（同日修订见第 5 节：记录并入项目动态流）
- 接受依据：用户 2026-09-28 指示——「然后删除项目也要在项目动态和审计日志里记载」，随后明确可见性口径——「项目动态要所有人能看到，审计日志管理员看到就行，要留有记录，记录谁删除了项目」；同日追加要求——「我要求记录要和其他动态放一块，而不是单独出来的」，据此把删除记录从独立区块改为动态流内的普通行。
- 修订关系：**修订 [ADR-049](ADR-049.md) 第 3 节**「删除后对所有人不可见（含管理员）」的绝对表述——被删除的项目本身仍然对所有人不可见，但「谁在何时删除了哪个项目」这条事实对全部登录用户可见。ADR-049 的软删除、权限与幂等口径不变；其中的「不可恢复」口径在本 ADR 时点仍成立，**已于同日由 [ADR-051](ADR-051.md) 修订**（新增逐条的还原与彻底删除动作）。
- 关联：[ADR-008](ADR-008.md)（审计只追加）、[ADR-012](ADR-012.md) / [ADR-039](ADR-039.md) / [ADR-048](ADR-048.md)（成员关系是授权唯一真相）、[ADR-042](ADR-042.md)（审计读取留痕）、[ADR-043](ADR-043.md)（项目生命周期三态）。

## 背景

1. ADR-049 落库后，删除项目已在**同一事务**里写两条记录：审计 `project.delete`（不可变，含项目编码与名称、操作者）与项目动态 `PROJECT_DELETED`（`visibilityScope: "MEMBER"`）。写入侧本身没有缺口。
2. 但两条记录在落库后都**读不到**：
   - 项目动态 `GET /api/v1/projects/{projectId}/activity` 是项目级作用域，而 `AuthorizedProjectScope` 已排除被删除项目 ⇒ 那条 `PROJECT_DELETED` 动态永远取不到；
   - 审计读取 `getAuditLogs` 按审计链（`SYSTEM` 或 `PROJECT:<id>`）查询，管理员**可以**按链查到，但前端「审计日志」页的审计链下拉只列出**活跃项目**，已删除项目的链没有入口。
3. 结果是「删了但没有记录可查」的产品缺口：数据库里证据齐全，界面上无法复核。用户因此要求把删除记载在两处可见：「项目动态要所有人能看到，审计日志管理员看到就行」。

## 决策

### 1. 新增删除记录读取路由（全部登录用户可读）

```
GET /api/v1/project-deletions  →  listProjectDeletions  →  200 ProjectDeletionPage
```

- `authPolicy: "session"`：只要 Session 有效（且用户未被停用）即可读，**不需要**项目成员关系、不需要 `is_admin`。匿名 401 `PROJECT_SESSION_REQUIRED`，停用用户按既有语义 401。
- 只读路由：无 CSRF、无幂等键、无 `If-Match`；Route Registry 的其余策略全部显式 `none`，`auditAction: "none"`（读取记录本身不写审计；审计读取留痕只属于 `getAuditLogs`，见 ADR-042）。
- 响应 `Cache-Control: no-store`；分页用既有的 `TimeCursorService`（命名空间 `PROJECT_DELETION`，TTL 15 分钟，绑定操作者），`limit` 1～50、默认 20；游标非法或换人使用统一 422 `PROJECT_DELETION_VALIDATION_FAILED`。

### 2. 记录只暴露「谁 / 何时 / 哪个项目」

`ProjectDeletionItem = { projectId, code, name, deletedAt, deletedBy: { id, name } }`：

- 事实来源是 `projects.deleted_at` / `projects.deleted_by` + `app.users` 的显示名（`JOIN` 实时取名，不落冗余快照）。
- **不**返回删除后的任何下级数据（模块、功能、任务、记录、成员、统计），**不**返回项目描述与状态，**不**提供按 ID 重新打开项目的能力。该路由是「登记簿」，不是「回收站」——ADR-049 第 9 节的非目标不变；它同时是项目动态渲染删除行的项目名与 ID 来源。
- 排序固定为 `deleted_at DESC, id DESC`，keyset 分页不重不漏。

### 3. 权限矩阵：删除记录是全体登录用户的读权限

| 调用者 | 结果 |
| --- | --- |
| 匿名 | 401 `PROJECT_SESSION_REQUIRED` |
| 任意活跃成员 / 其他项目成员 / 已移除成员 | 允许（返回全部条目的台账） |
| 停用用户 | 401 |
| 系统管理员 | 允许 |

台账**不**做项目范围过滤：删除本身是跨项目可见的组织级事实，与「成员关系决定项目可见性」不冲突——它不暴露任何项目内容，只暴露「存在过、被谁删了」。这也是本条路由不使用 `AuthorizedProjectScope` 的唯一原因，其他项目级读取路径的过滤口径完全不变。

### 4. 审计读取仍只对管理员开放，但补齐审计链入口

- `getAuditLogs` 保持 `authPolicy: "adminSession"`（现有契约未改动）：非管理员 403，匿名 401。
- 前端「审计日志」页的审计链下拉补给已删除项目：`PROJECT:<id> · <name>`，带 `已删除` 徽章与「<删除人> 删除」说明，来源就是同一份删除台账（复用 `listProjectDeletions` 第一页）；历史行、快照与筛选标签的项目名一并按台账还原，不再退化为「项目 #id」。
- 审计正文（快照、`before/after` 载荷）不因本次改动放宽。

### 5. 项目动态：删除记录是动态流里的普通一行

- 活动投影行的 `PROJECT_DELETED` 在删除的同一事务里写入，前端 `activity-labels.ts` 补上「删除项目」文案。
- **服务端放行（本次修订的核心）**：`ActivityQueryService` 先取 `AuthorizedProjectScope`；项目在范围内时按普通项目读，不在范围内但 `ProjectAccessQueryPort.isDeletedProject(projectId)` 为真时**放行但收窄**——只下发 `activityType = PROJECT_DELETED` 的投影行（`ActivityProjectionReader.read` 新增可选 `activityTypes` 过滤）。删除前的历史（含 `ADMIN_ONLY`）随项目一并退出可见范围，`includeAdminOnly` 不适用于该例外；此外「不存在」「无权访问」「已移除成员」仍是 404。

  > **2026-09-28 修订（[ADR-052](ADR-052.md)）**：本段的「只下发 `PROJECT_DELETED` 一行」已被修订为「下发该项目链的全部 `MEMBER` 可见动态」——已删除项目的创建到删除的完整过程对全部登录用户可见；仍不下发 `ADMIN_ONLY`，`includeAdminOnly` 依旧对该例外无效，404 判定不变。`ActivityProjectionReader` 的可选 `activityTypes` 过滤随之删除。
- **前端呈现**：删除行与其它动态共用同一套渲染——日期分组、时间轴、头像、`<操作者> + 删除项目 + 摘要 + 项目名` 与行尾「原始快照」。已删除项目不在项目列表里，因此页面的取数范围与项目名映射由 `listProjectDeletions` 第一页补齐（仅「全部项目」视图；锁定单项目视图不请求、也不出现删除行）。删除行**不**提供「查看对象」跳转，避免落到已删除项目的死链。
- 独立区块（原「项目删除记录」区块及其 `activity-deletions-*` 样式）整体下线，删除记录不再另起一节。

### 6. 非目标

1. **不**恢复被删除项目，**不**提供删除撤销、回收站或「待审删除」（ADR-049 第 8 节不变）。

   > **2026-09-28 修订（[ADR-051](ADR-051.md)）**：本条前半句已被修订——删除记录那一行现在提供「还原项目」与「彻底删除」两个动作（权限、数据库边界与审计口径见 ADR-051）。仍**不**提供回收站列表、批量操作与「待审删除」，本节其余非目标不变。

2. **不**给删除记录加入分页之外的**清单级**管理动作（导出、批量清理、重新分配编码）；逐条动作只有 ADR-051 的「还原项目」与「彻底删除」两个。
3. **不**把记录并进 `getAuditLogs`，也**不**把审计读取下放给普通成员；两条读路径的授权口径保持分离（ADR-042 的读取留痕只在管理员路径上）。
4. **不**为「有人删了项目」发通知：删除记录本身即公示渠道，通知会产生无法撤回的深链（ADR-049 第 6 节对通知的取舍不变）。
5. **不**缓存删除记录到 Session 或前端长生命周期对象，每次读取都以当前 Session 与实时用户名为准。
6. **不**为已删除项目提供任何内容入口：动态行不带「查看对象」，也不按项目 ID 重新开放模块 / 功能 / 任务 / 记录页面（ADR-049 第 9 节不变）。

   > **2026-09-28 修订（[ADR-052](ADR-052.md)）**：抑制「查看对象」的范围由删除行扩大为**已删除项目链的全部动态行**（历史行同样不留死链）；「不重新开放内容页面」与非目标其余各条不变。
